### 3.4 Docker 环境（重要坑位）

**WSL 下 dockerd 必须用独立进程启动**，用 systemd 的 `-H fd://` socket 激活方式会导致 daemon 周期性重启、容器永远显示「Up 几秒」：

```bash
wsl -d Ubuntu -u root -- bash -c 'systemctl stop docker.service docker.socket; \
  setsid nohup /usr/bin/dockerd -H unix:///var/run/docker.sock \
  --containerd=/run/containerd/containerd.sock > /var/log/dockerd-standalone.log 2>&1 < /dev/null &'
sleep 12

cd /opt/mall/src/docker
docker compose -f docker-compose.yml -f docker-compose.verify.yml up -d
# 等约 1 分钟，确认 Nacos/MySQL healthy
```

前端连 Docker 网关（**注意是 19000，不是默认 9000**）：

```bash
cd src/web && VITE_GATEWAY_TARGET=http://localhost:19000 pnpm dev
```

管理员账号在 `/opt/mall/src/docker/.env`（不提交），未配置时不会创建。

**WSL 命令引号坑**：多层嵌套引号会被吃掉，复杂命令要写成 `.sh` 文件再用 `bash /mnt/c/Temp/xxx.sh` 执行。

## 六、评审 PR 的方法（重要）

用两路独立复核，然后按原始证据裁定。**注意：子代理工具不支持指定模型，实际都走默认的 V4.1**，不要声称用了 6Astra。

### 6.1 客观门槛（先跑，不过就不合）

```bash
cd src/web
grep -rn "from 'element-plus'" src/views        # 应无输出
grep -rn "window.confirm\|window.alert" src/views  # 应无输出
grep -rn "records" src/views | grep -v -E '^\S+:\s*(\*|//|<!--)'   # 应无输出
git diff --name-only main | grep -E "api/|stores/|router/|components/ui/|style\.css|package\.json"
& $pnpm build > $null 2>&1; $LASTEXITCODE      # 应为 0
```

### 6.2 人工核对两条（复核中最容易出真问题的地方）

**① 请求与基线逐条比对**：方法、路径、字段名、类型不能变

```bash
git diff origin/main...origin/<分支> -- <文件>
git show origin/main:<文件>   # 对照原实现
```

**② 业务规则不能被改**：卖家端评审时发现过三处真问题，都属这一类

- 保存后不该重新拉取详情（基线注释明确说明会报错）却加回来了
- 审核备注参数被硬编码成空串，能力被削弱
- 重复清空状态 + 混用 `unwrapResult`/`isOk`

其余必查：成功判断是否用 `isOk`、防重复守卫、`confirmAction` 取消后是否 return、金额是否只除一次、三态是否分离、状态文案是否走 `constants/status.js`。

### 6.3 已知的误报

- 用 `git log --oneline "branch ^main"` 判断分支是否已合并**不可靠**（PowerShell 会把参数当整体），要用 `git merge-base --is-ancestor <sha> main`
- `si1oo` 搜提交记录搜不到，因为 git 作者名是 `sun`，同一人

# Element Plus UI 改造：总规划与个人任务书

> 2026-10-31 修订；本轮只细化规划，不安装组件库、不改业务代码。沿用方案 A，哭女统筹及基础层，业务任务强度 yy > 来财 > 韬哥 > fd。

## 1. 先统一事实与范围

- 前端共有 32 个 Vue 文件：29 个业务页面与 App、AppHeader、ProductCard 三个公共文件。完整分派见各人任务书，不按代码行数推断个人能力或任务难度。
- 继续采用 Element Plus，Tailwind 保留用于布局；不为了使用组件库把商品、订单、售后卡片强行改成表格。
- 使用仓库现有 pnpm 与锁文件。依赖声明范围不等于安装版本，开工时记录 Node/pnpm 版本与锁文件版本，由哭女统一验证兼容性。
- 后端、API 封装、认证 store、路由业务逻辑保持不变。允许在本人页面中修改组件导入、校验、loading、v-model 与事件适配；不得借机修改价格单位、角色权限、状态机、请求路径或幂等语义。
- 历史回归日志的模块数量为 14+6+9+27+29+40=125，不是旧文档的 121。本轮未运行测试，也不把历史通过等同当前验收。
- 旧 HTTP 脚本的 14 项检查不等于浏览器 E2E；其并发响应曾拼接后用 sed 提取，不能证明 50 个响应全部成功。本次验收必须保留可复现记录，不沿用“已完整验证”的结论。
- PR #76 尚未合并；PR #77 从其分支派生，目前对 main 的差异包含 #76 改动。不得称 main 已包含这些提交。哭女在开工前记录真实基线，先明确依赖合并顺序，不强推、不擅自合并。

## 4. 基础层只做必要共用能力

不预先强制制造七个封装组件。Element Plus 的表单、弹窗、表格允许直接使用统一样式和约定；只有重复行为明确时才抽组件。

| 公共能力 | 冻结合同 | Owner |
|---|---|---|
| 确认操作 | `confirmAction(options): Promise<boolean>`；确认 true，取消/关闭 false，取消不弹错误、不发请求；调用方必须检查返回值 | 哭女 |
| 分页（确有服务端分页的页面） | 若抽 UiPagination：`v-model:page`、`v-model:pageSize`、`total`；事件用 Vue 3 更新语义；UI 从 1 开始，调用方显式适配原接口；改变 size 重置页码且只请求一次 | 哭女 |
| 空/加载/错误 | 优先 el-empty、el-skeleton/v-loading、el-alert；失败不能伪装成“暂无数据”，重试保留用户筛选 | 哭女制定规范，各页实现 |
| 表单/弹窗 | 原生 el-form/el-dialog；表单规则与现有校验一致，弹窗 model-value，不另造 visible 同义接口；关闭后的草稿/校验清理策略统一 | 哭女制定规范 |
| 商品卡片 | 保持现有 props、click(product) 事件、分转元显示和图片回退；调用方不修改组件 | 哭女 |

冻结合同后只做向后兼容修改，不在并行开发中让四个人反复迁移封装接口。

## 5. Tailwind 与 Element Plus：验证后再冻结

旧计划的 `source(none)` 只关闭自动扫描，**不会禁用 preflight**。官方说明：[Tailwind Preflight](https://tailwindcss.com/docs/preflight)。CSS 引入先后也不能脱离 cascade layer 作“一定修好”的保证。

基础层先用独立演示组件验证候选方案：显式导入 Tailwind theme 与 utilities，不导入 preflight；补齐仍使用原生标签所需的基础样式，再比较按钮、输入框、表格、卡片、弹窗和焦点样式。示意（不是已经验证的配置）：

```css
@layer theme, base, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
```

检查原生元素 box-sizing、默认 margin、border-style、图片尺寸等是否依赖旧 reset；不使用全局 `!important` 或全局 `.el-*` 覆盖硬压。验证成功后把唯一方案、截图和生产 build 结果写进基础层 PR。扫描范围优化与 reset 策略是两件事。

## 6. 所有人遵守的行为合同

1. 保持接口请求的方法、参数、类型、单位、ID 与成功判断。`isOk` 与 `unwrapResult` 不可混用：`code=0,data=null` 的写操作仍可能成功。
2. 金额展示分转元，不把“元”再次当分发送；库存整数、数量边界、未知状态回退保留。
3. HTTP 错误和业务错误都要显示；输入错误就地提示；取消确认不是失败；同一失败只提示一次。401 沿用现有 auth:expired 机制。
4. 提交按钮 loading + 防重复触发；finally 恢复状态。不要把整个页面用 v-if 反复卸载造成输入丢失。
5. 日期选择器输出必须还原原接口格式，不能把 Date 对象直接替换原字符串；分页、筛选与状态条件保持原语义。
6. 上传只有原来存在的页面才迁移；保留 FormData 字段、鉴权、限制和返回值解析。不让 el-upload 默认动作与已有上传函数各请求一次。
7. data-testid 用 `页面-控件-动作`，行内用业务 ID，不用数组下标；这是新增测试约定，不声称仓库已有 DOM E2E。
8. 键盘可提交/取消，标签关联输入，焦点可见；弹窗关闭焦点返回触发按钮。360/768/1440/1920 宽度抽查，无整页横向溢出；宽表可容器内滚动。

## 8. 验收与证据

每批 PR 附：任务 ID、基线/提交号、改前后截图、场景结果（通过/失败/未测）、去敏后的 Network 字段对照、build 输出、已知风险。不得提交密码、JWT、完整 HAR 或真实个人信息。

总验收要求：
- 按锁文件安装与前端生产 build 成功；必要时记录产物体积变化，不编造增量数字。
- 浏览器真实点击：登录→浏览→加购→地址→下单→MOCK支付→订单详情；卖家新建/编辑→管理员审核→上架；发货/收货/评价与售后按现有能力走通。
- 各角色误访问、401、业务失败、网络失败、空态、重复点击均有结果。权限验证不以“菜单隐藏了”代替服务端拒绝。
- HTTP API 回归与浏览器 UI 回归分别记录。并发若重测，逐个解析响应、核对非空 ID/业务码/数据库不变量；不可拼接 JSON 后声称全部通过。
- 后端回归作为集成基线，保留真实退出码、各模块报告和总数；后端单测通过不能证明 UI 正确。已有后端缺陷另立跟踪，不在 UI 任务里顺手修。
- 实验三截图和报告由哭女同步，未测试部分明确标注。

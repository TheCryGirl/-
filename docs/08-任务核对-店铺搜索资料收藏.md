## 六、验证方式

本轮在本机**没有 Maven 与 Node 环境**，未执行 `mvn test` 与前端构建，采用以下手段自检：

1. **XML 可解析**：5 个服务全部 `pom.xml` 与 MyBatis 映射文件逐个解析通过；
2. **Java 静态检查**：286 个 `.java` 文件括号平衡、`com.mall.*` 包内 import 均能对应到实际类型；
3. **Vue 结构检查**：所有 `.vue` 的 `<template>` / `<script>` 开闭配对完整；
4. **契约与实现对照**：前端 `api/index.js` 的每个方法逐条核对后端 `@RequestMapping` 路径与方法；
5. **测试配置对齐**：为 `product-service`、`user-service` 的测试配置补充 `services.*-url`，让新增的 Feign 客户端在测试中走「不可达地址 → 按正常营业放行」分支，不影响既有单测断言。

> 建议在有构建环境的机器上补跑：`mvn -q test`（product / order / user）与 `npm run build`（web）。

## 八、收尾复核发现并修复的问题

第二轮通读时发现并已修复，均可从代码定位：

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| `ShopMapper.xml#updateInfo` 用 `<if test="!= null">` 拼 `SET` | 卖家清空头像 / 简介 / 联系方式后保存无效，旧值残留 | 改为整体覆盖赋值，空值即清空（与 `PUT /api/shops/mine` 语义一致） |
| 历史数据可能一条默认地址都没有 | `defaultAddress` 恒为空，下单页无法自动选中 | `AddressServiceImpl#listAddresses` 检测到无默认时把最早一条补为默认，无需手工修数据 |
| 价格元转分直接用 `Number(x) * 100` | 如 `50.5 × 100 = 5050.000000000001`，后端按 `Long` 解析会失败 | 前端改为 `Math.round(Number(x) * 100)` |
| 购物车把 `SUSPENDED` 一律提示「商品已下架」 | 用户无法区分是店铺被停用还是商品下架 | `CartServiceImpl` 按状态分开提示「店铺已停用」/「商品已下架」 |
| 三个列表页各自拼时间串 | 展示不统一（带 `T`、带秒） | 新增 `src/web/src/utils/format.js#formatTime`，店铺管理 / 收藏 / 足迹统一展示到分钟 |
| `user-service` 存在未使用的错误码 `SHOP_SUSPENDED = 20008` | 错误码表与《05-接口契约》对不上 | 删除该码，`FAVORITE_NOT_FOUND` 由 20009 改为 20008 |

复核后再次执行静态自检：XML 25 个可解析、Java 286 个括号平衡且 import 均可定位、Vue 与前端相对 import 无缺失。

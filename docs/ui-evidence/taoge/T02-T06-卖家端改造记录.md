## 二、逐页改造与「必须保留」核对

### T02 商品新建 / 编辑（最高风险）

| 检查项 | 结论 | 位置/做法 |
| --- | --- | --- |
| 主图是 URL 输入，不是上传 | ✅ 未引入 `el-upload`，也未新增上传接口 | `el-input v-model="form.mainImage"`，下方注明「本页不做上传」 |
| 新建与编辑是两种模式 | ✅ 仍然是两段互斥的 `v-if="!isEdit"` / `v-if="isEdit"` | 新建：可增删初始规格行，至少一行；编辑：已有规格表 + 新增 |
| 编辑已有 SKU 只能改库存与新增 | ✅ 已有规格表没有删除/改价入口 | 表格列固定为 规格 / 单价 / 已锁定 / 可售库存；操作列只有「保存库存」 |
| 元转分不二次转换 | ✅ `Math.round(Number(yuan) * 100)`；输入框就是元，提交前只调用一次 `toCents` | 校验：`12.34 → 1234`、`19.99 → 1999`、`0.07 → 7`（与 JS `Math.round` 同 IEEE-754 语义，已复算） |
| 库存清空不能传 NaN | ✅ `toStock()`：`null`/空/NaN/负数一律 0，且 `Math.floor` 取整 | 新建行与已有 SKU 的 `el-input-number` 都走它 |
| 保存后 loadProduct 的既有风险 | ⚠️ 保持原流程 | `saveProduct()` 内仍 `await loadProduct()`；若因状态变化读不到，属既有问题，未改业务流 |

## 五、有环境时的手测清单

1. **T02**：新建商品填两行规格（12.34 元 / 19.99 元）→ 提交后抓包确认 `skus[].price` 为 `1234` / `1999`；清空库存输入框再提交，确认请求体是 `0` 而不是 `null`/`NaN`。
2. **T02 编辑**：进入已有商品，确认表中无「删除」按钮，改库存后点「保存库存」只发 `PUT /products/skus/{skuId}/stock`。
3. **T03**：点「发货」→ 取消，Network 无请求；再填单号确认，只有一次 `POST .../ship`，成功后该单从列表消失。
4. **T04**：点「驳回」「同意」时先取消，确认无请求；确认后失败（模拟后端 500）不提示成功、列表不刷新。
5. **T05**：分别对 PENDING / BUYER_SHIPPED(退货退款) / BUYER_SHIPPED(换货) / APPROVED 四种状态各走一次，确认只出现对应按钮。
6. **T06**：选一张 <5MB 图片，Network 只出现一次 `POST /api/products/images`；选 >5MB 文件应有提示且不发请求；上传后不保存直接刷新，确认未写库。

## 六、复核修复（`feature/ui-taoge-seller-review`）

第二轮逐页复核发现的问题与修复：

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 删掉了页面 `<h1>` | `App.vue` 与 `AppHeader.vue` 都不渲染 `meta.title`，删掉后这 6 页**完全没有标题**；`git grep '<h1'` 检查发现其余 16 个页面（含 `AdminUsers`、`Login`）都保留了标题 | 6 页恢复 `text-lg font-semibold text-gray-900` 标题，文案与 `router meta.title` 一致；T02 按模式显示「发布商品 / 编辑商品」，返回链接移到右侧 |
| `el-image` 缺 `#error` 插槽 | 图片 404 时显示浏览器破图图标（规范 5.3 要求兜底） | T01 商品图、T06 店铺 Logo 补 `#error` 占位 |
| 列表计数用 `list.length` | `/products/mine` 默认一页 20 条，商品超过 20 个时会以为商品丢失 | 改读后端 `total`；当 `total > list.length` 时用 `el-alert` 提示「共 X 条，当前仅显示前 N 条」，并在注释里指向 `mine()` 缺参数 |
| 编辑模式被分类接口拖住 | 原写法 `canSubmit` 依赖分类列表，分类接口失败时编辑已有商品也无法保存（原代码是可以的） | `canSubmit` 只在新建模式要求分类列表可用；编辑模式沿用商品原有 `categoryId` 即可保存 |
| T04 残留未使用的 `manualRef` | 无效代码 | 删除定义与模板 `ref` |
| 证据文档把发货方法写成 POST | 与实际不符 | `orderApi.ship` 是 `PUT /orders/{orderId}/ship`，已改正 |

复核后重新跑静态自检：Vue 结构、import、禁写/禁改项全部通过；并打印全部页面 `<h1>` 与路由标题逐个对照（6 页均一致）。

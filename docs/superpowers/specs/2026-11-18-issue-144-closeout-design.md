# #144 商家入驻与结算收尾设计

基线：`main` @ `01cf471`。已合入入驻、基础结算和首轮并发回归修复；本设计只补已确认的验收缺口。#145 作为迭代跟踪，不以关闭 Issue 代替功能验收。

## 1. 入驻与商品发布

三个条件均满足才允许新建、重新上架或通过审核使商品首次公开：入驻 `APPROVED`、营业 `ACTIVE`、已登记保证金（金额大于 0）。保证金仍由管理员登记，不在线收款。禁止通过管理端商品审核或店铺恢复营业让无资格的草稿变成在售。历史在售商品不做批量下架；已经在售的商品可正常下架。保存店铺资料与处理既有订单不依赖保证金。店铺停用与入驻状态仍分开，不用保证金改写审核结论。卖家端用同一口径展示按钮和区分原因；公开店铺接口不暴露资质或保证金字段。查询店铺资格失败时，新增/上架操作不放行。

## 2. 类目快照与佣金

在订单明细写入可空的下单类目 ID；老库增加可空列，不猜测历史类目。多商品子订单先按明细原小计比例分配实际应收（含运费及折扣影响），金额以分存储，按稳定顺序分配余数，分配总额必须等于该子订单净实收。店铺费率覆盖整个子订单；没有店铺规则时分别使用各行类目费率，未配置或无类目快照的明细使用平台费率，平台费率缺失时为 0。对各份金额乘万分比费率后求和，每个子订单只进行一次四舍五入到分（整数或 BigDecimal，不使用浮点数）。结算明细记录计算所用分配权重与适用费率，以后退款沿用原费率，不回读可变的商品类目和政策；老结算单不回写已打款金额。佣金规则由管理员维护，限定范围、目标和费率，卖家无写权限。

## 3. 退款与结算

只统计成功退款，未完成或拒绝的退款不扣减。生成及核对结算时，以订单实付扣减该订单累计成功退款后的非负净额计算；部分退款按净额重算，已全额退款且尚未入账的订单不产生正额明细。可编辑结算单更新原明细并从明细重新汇总表头。已打款单及其打款记录不可改写，退款造成的应结差额写入独立的冲减记录，后续符合条件的月结单消费，原单及调整单可交叉追溯。

使用本地已成功退款记录作为可重试输入，不新增队列或外部转账调用。生成和标记打款前必须核对已入账订单，不只扫描从未结算的订单；查询接口保持只读。已打款后的差额从原结算周期的下一期起结转，若目标期已冻结则顺延到首个未冻结的期间。锁定结算单及明细后同步累计退款及调整，用数据库唯一约束阻止重复入账；并发生成、退款终态重放或进程重启不能重复扣减。若调整超过本期新增收入，只抵至应结金额为零，剩余继续结转，不登记负向打款。

仅允许自然月结束后标记打款。提交时重新核对可结算订单及退款，并比较管理员确认的应结金额；若金额变化，返回提示，管理员重新确认后才能标记。金额未变时，在同一事务冻结结算单并记录唯一凭证编号、操作人、金额、时间和可选备注。与打款同时到达的退款以可观察的落账先后归入原单或后续冲减，不得漏记。该接口不向任何渠道发起转账。

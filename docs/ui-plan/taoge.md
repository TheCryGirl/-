## 3. T02 的细化步骤（最高风险页面）

1. 分别记录“新建商品”“编辑商品”的可编辑字段，不把两个模式合并成一套可任意改SKU的表单。
2. 保留title/subtitle/mainImage/categoryId结构；mainImage继续是URL字符串，不能因为有el-upload组件就新增接口。
3. 新建SKU：可增加/删除输入行，至少保留一行；沿用空规格行处理规则与有效SKU判断，不额外新增业务约束。
4. 单价输入为元，沿用 `Math.round(Number(yuan)*100)` 转分；测试12.34→1234，不出现二次转换。
5. 库存沿用原整数/非负处理；el-input-number清空会出现null，要显式适配原规则，不能传NaN。
6. 编辑已有SKU：原代码只调整库存及新增SKU，不允许删除既有SKU或任意改价；组件表格不自动赋予编辑权限。
7. 提交区loading并保留isOk判断。成功后原代码存在loadProduct调用，保存导致商品状态变化后的读取权限风险先登记，不在UI任务擅自改业务流程。
8. 分类加载失败与空分类的区别在PR说明；无法提交时给可理解提示，不使用硬编码分类冒充成功。

## 4. 六页手测矩阵

| 场景 | 操作 | 期望 |
|---|---|---|
| 商品空/错误 | T01无商品、筛选空结果、断网 | 空与失败区别显示，重试不改筛选 |
| 商品编辑跳转 | T01点击编辑→T02 | 路由productId与所点商品一致 |
| 新建SKU | 两行不同规格/价格；删除一行；只剩一行再删 | 原规则保持，提交SKU数组正确，无空行误提交 |
| SKU数值 | 12.34元、0/负/非数价格，库存0及清空 | 合法转分，非法按原规则拒绝或规整，不发送NaN |
| 编辑SKU | 已有SKU调整库存，再新增SKU | 既有skuId保留，不新增删除已有SKU操作 |
| 保存失败 | 模拟业务失败和网络失败 | 不显示成功，不丢表单，按钮恢复 |
| 发货 | T03合法物流/缺字段/重复点击 | 原校验生效，一次写请求，成功刷新真实状态 |
| 退款 | T04确认/取消/拒绝/后端拒绝（按原入口） | 取消无请求，金额与ID正确，失败不推进状态 |
| 售后 | T05每种可用状态动作各走一次 | 不可执行动作不出现；刷新后状态来自后端 |
| 店铺资料 | T06保存及Logo上传失败/成功 | 原FormData字段、限制与返回解析不变，不双请求 |
| 权限 | 非卖家/其他卖家资源/401 | 沿用原权限拒绝，不以菜单隐藏代替检查 |
| 响应式 | 360/768/1440/1920与长商品名 | 无整页横向溢出，SKU表可局部滚动，焦点可见 |

用开发数据，跨角色状态测试约定统一测试订单，不同时操作同一订单互相污染结果。

## 二、任务 #13：前端从二手平台模型改造成商城

原 `src/web` 已有目录复用，但业务页面需按商城模型重写，工作量不低于一个后端服务。当前页面与路由覆盖如下（`src/web/src/router/index.js`）：

| 任务要求 | 页面 | 说明 |
| --- | --- | --- |
| 购物车（UC-15~18） | `views/Cart.vue` | 列表、勾选、改数量、删除、失效商品置灰、去结算 |
| 确认订单（UC-19） | `views/OrderConfirm.vue` | 收货地址选择、明细核对、幂等令牌下单 |
| 支付（UC-20~21） | `views/OrderPay.vue` | 创建支付单、MOCK 渠道支付、支付状态回显 |
| 订单列表（UC-25） | `views/OrderList.vue` | 按状态筛选、分页 |
| 订单详情（UC-26） | `views/OrderDetail.vue` | 明细、取消、确认收货、申请退款 |
| 卖家侧（UC-28 等） | `views/seller/*` | 商品管理（上下架）、发布/编辑商品与 SKU、待发货、退款审核 |
| 管理员侧 | `views/admin/*` | 用户管理（冻结/角色）、商品审核、售后仲裁 |

路由守卫按 `meta.requiresAuth` 与 `meta.role` 做登录与角色拦截，`ADMIN` 可访问卖家与管理员页面；接口层统一走 `api/index.js` 的 axios 实例，401 时清理登录态并广播 `auth:expired`。

## 三、本轮改动（fix/12-13-task-gaps）

核对中发现两处「代码在、功能不通」的问题，一并修复：

### 1. 商品审核页取不到待审核商品

- 现象：`AdminProducts.vue` 调 `GET /api/products?status=PENDING`，但控制器没有 `status` 参数，且 `publicWhere` 硬过滤 `p.status = 'ON_SALE'`，管理员永远看不到待审核商品。
- 修复：`ProductController#list` 增加 `status` 参数与 `X-User-Role` 请求头；`ProductService#list` 中仅当角色为 `ADMIN` 且传了合法状态时走新增的管理列表查询（`ProductMapper#selectAdminList` / `#countAdmin`），普通用户仍按 BR-08 只看在售且在库商品。契约 3.3 同步补充 `status` 参数说明。
- 测试：`ProductServiceTest#adminCanListPendingProductsByStatus` 覆盖「普通用户看不到待审核商品 / 管理员能按状态查出 / 非法状态被拒绝」。

### 2. 前端写操作按 HTTP 状态判断，业务失败静默

统一响应在业务失败时仍是 HTTP 200（`code != 0`），只写 `try/catch` 会把失败当成功。以下位置改为按 `isOk(data)` 判定，失败即提示并回滚界面状态：

`Cart.vue`（勾选/改数量/删除，失败后重新拉取购物车）、`OrderDetail.vue`（取消/确认收货）、`OrderPay.vue`（MOCK 支付）、`SellerProducts.vue`（上下架）、`SellerProductEdit.vue`（保存/发布/新增规格/调库存）、`SellerShipments.vue`（发货）、`AdminProducts.vue`（审核）。列表加载统一改用 `unwrapResult`，避免把错误包装当数据渲染。

### 3. JWT 密钥收紧为纯环境变量

原先 `user-service` 与 `gateway` 的 `jwt.secret` 带有一份硬编码的开发默认值，与「禁止硬编码」不符。现改为 `${JWT_SECRET:}`：

- 未设置时 `JwtUtil` 与 `JwtAuthFilter` 在**启动阶段**直接抛出「JWT_SECRET 长度至少 32 位」，不会带着弱密钥跑起来；
- `src/scripts/dev.ps1` 一键启动时若未设置会自动注入开发用密钥并打印提示，本地开发体验不变；
- `src/docs/本地启动指南.md`、`src/docs/一键启停说明.md` 同步说明；
- 测试用配置 `src/user-service/src/test/resources/application.yaml` 自带测试密钥，不受影响。

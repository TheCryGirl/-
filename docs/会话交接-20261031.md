## 三、下一步：修 #74（正在进行）

### 3.1 缺陷是什么

`Issue48OrderConcurrencyTest.concurrentDuplicateIdempotencyKeyReturnsOneOrder`

- 50 线程并发、同一幂等键下单
- 断言 `productClient.reserve(...)` 只调 1 次
- 实际有时被调 3 次（**库存可能被多扣**，订单表始终只有 1 笔，唯一键有效）
- 复现率不稳定：单独连跑 8 次复现 1 次；某些批次 5 次复现 3 次

### 3.2 根因

`OrderService.java` 的 `resume()` 第 286-291 行，是「读状态 → 判断 → 补做预占」的 TOCTOU 窗口：

```java
OrderIdempotency latestState = idempotencyMapper.selectByKey(existing.getIdemKey());
if (latestState != null && latestState.getStatus() == IdempotencyStatus.SUCCESS) {
    return createResponse(order);
}
// 多个线程可能同时通过上面的检查 → 各自 callReserve()
```

**问题1（最关键，决定修复是否有效）**
现在的 `create()` 流程里，**首个请求**走 `createFresh()`，它**无条件下**执行 `callReserve()`；`resume()` 才是后续并发请求走的。那么只在 `resume()` 里加抢占能否彻底解决？会不会出现「首个请求在 createFresh 调一次 + 某个 resume 请求抢到 RESERVING 又调一次」？即：`createFresh()` 是否也必须参与同一套抢占机制？

**问题2**
抢占成功后进程崩溃，状态永远卡在 RESERVING 怎么办？现有 `deleteStale` 只清理 `status='PROCESSING'` 且超时的记录（见 `IdempotencyMapper.xml`）。是否需扩展？

**问题3**
`awaitOrderCreated()` 第 343 行有 `if (latest.getStatus() != IdempotencyStatus.PROCESSING) return null;`，引入 RESERVING 后会被误判为「已结束」而提前返回 null，导致调用方抛「下单处理中」。这个判断是否要改？

**问题4**
有没有比「新增 RESERVING 状态」更小的改法？候选：
- 应用层 `ConcurrentHashMap` per-key 锁（单机部署够用，改动最小）
- `SELECT ... FOR UPDATE` 行锁
- 复用现有状态位

约束：**最小改动 + 单机部署 + 课程项目**，且 order-service 属 yy（`yynqycq`）负责，跨目录改动需先说明。

## 七、重要经验与坑位（本轮新增）

### 7.1 网络与代理

- **`gh` 必须带代理**：`$env:HTTP_PROXY='http://127.0.0.1:7890'`，清掉代理会 TLS 超时
- 代理在某些时段不稳定，GitHub 会在 200 与 000 之间反复；重试前先用 `curl.exe -s -o NUL -w "%{http_code}"` 探活
- `gh` 报 `EOF` 时**操作可能已经成功**，先 `git fetch` 核实再重试
- PowerShell 里 `$?` 不可靠，看 `$LASTEXITCODE`

### 7.2 Docker（WSL2 路线）

本机**没有 Docker Desktop**，验证走的是 WSL2：

- 已装 Ubuntu 26.04（`wsl -d Ubuntu`）、docker.io 29.1.3、docker-compose-v2 2.40.3
- **`~/.wslconfig` 里加了 `networkingMode=mirrored`**，这是让 WSL 能用上 Windows 代理（127.0.0.1:7890）的关键，否则镜像拉不下来
- 拉镜像前需给 dockerd 注入代理：`source /etc/docker/proxy-env` 再 `exec dockerd`
- **dockerd 会被 WSL 会话回收**，用 `Start-Job` 包一层 `wsl -d Ubuntu -- bash -c "exec dockerd"` 保活
- systemd 的 `docker.socket` 会反复拉起旧实例抢跑，已 `systemctl mask`
- 项目复制到了 `/opt/mall/src`（避免中文路径问题）
- 宿主端口被占用时用 `src/docker/docker-compose.verify.yml` 覆盖到 1xxxx 段

**启动全栈**：
```bash
cd /opt/mall/src/docker
export JWT_SECRET='...' DB_PASSWORD='...' INTERNAL_TOKEN='...' MOCK_SECRET='...'
docker compose -f docker-compose.yml -f docker-compose.verify.yml up -d
```

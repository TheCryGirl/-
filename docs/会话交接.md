### 3.4 GitHub 操作


**看板状态选项 ID**（固定）：

- `Todo` = `f75ad846`
- `In Progress` = `47fc9ee4`

**踩过的坑**：

- `gh` 经常 `unexpected EOF` 报错，实际**操作可能已经成功**，重试会提示 "already merged"
- PowerShell 里 `$?` 不可靠，要看 `$LASTEXITCODE`
- 关闭 Issue 时 GitHub 会自动把看板改成 Done（如果已关联）
- **代理必须显式带上**（`HTTP_PROXY`/`HTTPS_PROXY` = `http://127.0.0.1:7890`）；清掉代理会 TLS 超时
- 看板 JSON 落盘用 `Set-Content -Encoding UTF8` 会带 BOM，`ConvertFrom-Json` 报「无效的 JSON 基元」；改 `[IO.File]::WriteAllText` 配 `UTF8Encoding $false`
- `gh project item-list --jq` 传复杂表达式可能长时间挂起，简单的 `--format json` 再本地解析更稳

### 4.5 修复的三个真实缺陷（重点，报告里要用）

**（1）并发取消导致库存重复释放（#48 发现）**

```java
// 错误代码：markCancelled 返回 0 后仍然继续释放
int updated = orderMapper.markCancelled(orderId, ...);
if (updated == 0) { /* 只判断状态，不判断是否已释放 */ }
releaseInventory(orderId);   // 无条件执行
```

**修复**：`markInventoryReleased` 改为抢占式

```sql
UPDATE `order` SET inventory_released = 1
WHERE order_id = ? AND is_deleted = 0 AND inventory_released = 0
```

抢到（影响行数 1）才真正释放，远程失败则用 `resetInventoryReleased` 复位交给补偿。

**（2）MySQL 语法不兼容导致服务起不来（#47）**

```sql
-- MariaDB 语法，MySQL 8 报 ERROR 1064
ALTER TABLE sku ADD COLUMN IF NOT EXISTS low_stock_threshold INT NULL;
```

**修复**：列并入 `CREATE TABLE`，老库另给 `migration-47-low-stock.sql`（用 `information_schema` 判断后 ALTER，幂等）。

**为什么单测没发现**：H2 测试 schema 写的是标准语法，H2 能过、MySQL 挂。

**（3）并发同幂等键重复扣库存（#49~#52 合并后发现）**

`resume()` 看到 `PROCESSING` 直接抛「下单处理中」——违背幂等语义。

**修复两步**（缺一不可）：

1. 改为轮询等待（最多 3 秒）等首个请求落库
2. 等待成功后**重读幂等记录**，已是 SUCCESS 直接返回，否则才补做预占

只做第 1 步会导致 `reserve` 被调两次（测试从 Error 变 Failure 暴露的）。

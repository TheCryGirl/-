# 本机演示：双击启动

## 最短使用方式

1. 打开仓库根目录，双击 [启动演示.cmd](../启动演示.cmd)。
2. 按提示输入本机 MySQL 密码，输入时不显示字符。若当前终端已经设置 `DB_PASSWORD`，不再询问。
3. 等待窗口依次显示 Nacos、五个业务服务、网关和前端“就绪”。全部成功后自动打开 <http://127.0.0.1:5173/products>。
4. 可以关闭启动窗口。服务在后台继续运行；再次双击会复用同一项目已正常运行的组件，不重复启动。即使上次等待超时、进程尚未绑定端口，仍会核对 PID、启动时间和产物路径，等待原进程，不重复创建。
5. 现有前端还必须有本启动器记录的 `9000` 网关目标；手动启动或旧版本记录无法证明代理目标时会明确报冲突，避免误连 `19000` 的另一套 Docker 数据。请自行关闭该前端后再启动，不会强制结束它。

注意：每次冷启动仍需输入数据库密码，这是避免明文口令落盘的设计，不是脚本缺陷。已在运行的全栈不需要重新输入密码。登录页面所需的演示账号口令与数据库口令不是一回事。

## 本机现成依赖

- 已有本机 MySQL，监听 `127.0.0.1:3306`；脚本不会安装、重置、提权启动或停止 MySQL。
- JDK 17（优先 `DEMO_JAVA_HOME`，之后检查 `JAVA_HOME`、`C:\Tools`、常见 Java 安装目录；不会误用现有 JDK 24）。
- Nacos 2.x，`target/nacos-server.jar`。依次检查 `DEMO_NACOS_HOME`、`%LOCALAPPDATA%\Programs\nacos`、`C:\nacos`、仓库内 `nacos`，不依赖 `startup.cmd`。
- Node.js 22.12+ 或24，已安装的 `src/web/node_modules`。直接调用本地 Vite，不依赖全局 pnpm。
- 六个已打包 JAR：`src/<服务>/target/*.jar`。入口启动现有产物，不自动拉代码、不联网安装依赖，也不自动覆盖构建结果。

缺少 JAR 时需先用 JDK 17 在 `src` 下运行 `mvn -B package`；前端依赖缺失时在 `src/web` 下用 `pnpm install --frozen-lockfile` 安装。新克隆的仓库不包含 JAR、node_modules、MySQL 数据或 Nacos，这个入口不等于免依赖安装包。

## 脚本的边界

- 仅本机演示；前端只监听 `127.0.0.1:5173`，不开放局域网或公网。
- 不修改用户／系统 `JAVA_HOME`、PATH、注册表、防火墙、数据库权限。
- 不保存数据库密码，不把它放在命令行参数中；只临时传给需要的业务子进程，随后恢复父进程环境。不会写 `.env`。
- 对于项目现有开发环境，复用旧 `dev.ps1` 的本地开发 JWT 默认值；这不是生产配置。若自设 `JWT_SECRET`，全栈必须一致。
- 启动子进程前清除 `ADMIN_BOOTSTRAP_ACCOUNT/PASSWORD`，不会意外创建或恢复管理员。
- 不结束任何既有进程。遇到端口被其他项目占用，显示端口和 PID 并停止，交给用户处理。
- 日志每次保存在独立 `logs/demo-<时间>-<PID>/`，不覆盖此前运行记录；进程归属记录在 `.run/demo-processes.json`，二者都在 `.gitignore` 中。
- 应用本身仍会按原配置执行建表/基础数据初始化；启动器不额外执行迁移或重置数据。旧库升级迁移按 README 手工处理，不自动替用户执行 DDL。
- 该入口不修复应用本身的已知功能与安全问题，也不代表生产部署验收。

## 成功判据

不是“端口开了就成功”。入口依次确认：

1. Nacos 服务列表 API 可用。
2. 每个后端 `/actuator/health` 返回 `UP`。
3. 网关 `/api/products` 返回业务 `code=0`。
4. 前端首页 HTTP 200，且前端代理 `/api/products` 返回 `code=0`。
5. Nacos 列表含六个服务。
6. 最后才调用系统默认浏览器打开演示页面。

默认每个组件最多等待150秒；启动失败不强制终止其他服务，保留诊断日志。修正后再次双击，可复用已起来的组件。

## 辅助检查与测试

不启动进程、不询问密码的依赖检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\src\scripts\demo.ps1 -CheckOnly
```

自动化运行时可使用 `-NonInteractive -NoBrowser`；缺少进程级 `DB_PASSWORD` 就明确失败，不读取终端输入。此模式不得将口令硬编码在脚本或提交中。

组件行为测试（不访问业务数据库、不启动商城服务）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\src\scripts\tests\demo-launcher.tests.ps1
```

原来的 `src/scripts/dev.bat` 仍保留给旧开发流程使用，但它没有前端管理，且 `stop` 按端口找进程。不要把它当本入口的安全停止器使用。本入口没有“按端口全部杀掉”的自动停止操作。

# yy：管理端与商品详情任务书

返回[总规划](../10-UI改造任务规划.md)。11页，预算6–8人日（8小时/日，含自测与返工），任务强度最高。重点是敏感操作、权限、数据解释与多类异常，不是机械把所有页面换成表格。

## 4. 必做验收：操作→期望

### 管理操作
1. 用正确角色进入Y01–Y10，各页首次加载、空结果、加载失败分别展示；失败不能显示为“0条数据”。
2. 筛选后执行行操作：确认目标ID与当前行一致，不因排序/刷新作用到另一行。
3. 点击操作再取消/按Esc：Network无写请求，无“操作失败”；确认一次只发一次，按钮忙状态恢复。
4. 模拟业务失败（HTTP200但code非0）和网络失败：保留筛选与用户输入，显示有意义错误，不先展示成功状态。
5. 非管理员直接访问路径及会话过期：沿用原守卫/401，不能只靠隐藏菜单作为权限验证。

### 配置与审计
6. Y08输入1、1440以及1、500边界可提交；0、超上限、小数被拒绝，原数字转字符串的请求体不变。
7. 保存失败不显示成功；保存成功按原逻辑刷新配置/历史。未知配置键沿用原处理，不扩展校验语义。
8. Y07日期区间选中、清空、翻页、改变筛选：发出的参数格式与改造前一致；分页点击只发一次请求。
9. Y09/Y10用零值、大金额、未知状态、空结果核对展示；不把零值写成“--”，不重复除100。

### 商品详情
10. 从来财的商品列表点入Y11，确认路由ID和返回路径；选择两个不同SKU，数量/价格/库存展示随原规则变化。
11. 数量为最低值、库存上限、超上限、缺货、商品不可售：按现有规则禁用或报错，不新增虚假库存。
12. 未登录点击需登录动作、已登录加购、重复快速点击、业务拒绝：提示与请求数合理；加购成功仍落到来财负责的购物车。
13. 评价长文本、空图片、未知状态不撑破布局。收藏等原有动作按原代码回归，不删掉换版时“不好做”的入口。

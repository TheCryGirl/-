# 本机演示：双击启动

## 最短使用方式

1. 打开仓库根目录，双击 [启动演示.cmd](../启动演示.cmd)。
2. 按提示输入本机 MySQL 密码，输入时不显示字符。若当前终端已经设置 `DB_PASSWORD`，不再询问。
3. 等待窗口依次显示 Nacos、五个业务服务、网关和前端“就绪”。全部成功后自动打开 <http://127.0.0.1:5173/products>。
4. 可以关闭启动窗口。服务在后台继续运行；再次双击会复用同一项目已正常运行的组件，不重复启动。即使上次等待超时、进程尚未绑定端口，仍会核对 PID、启动时间和产物路径，等待原进程，不重复创建。
5. 现有前端还必须有本启动器记录的 `9000` 网关目标；手动启动或旧版本记录无法证明代理目标时会明确报冲突，避免误连 `19000` 的另一套 Docker 数据。请自行关闭该前端后再启动，不会强制结束它。

注意：每次冷启动仍需输入数据库密码，这是避免明文口令落盘的设计，不是脚本缺陷。已在运行的全栈不需要重新输入密码。登录页面所需的演示账号口令与数据库口令不是一回事，见下节「演示账号」。

## 本机现成依赖

- 已有本机 MySQL，监听 `127.0.0.1:3306`；脚本不会安装、重置、提权启动或停止 MySQL。
- JDK 17（优先 `DEMO_JAVA_HOME`，之后检查 `JAVA_HOME`、`C:\Tools`、常见 Java 安装目录；不会误用现有 JDK 24）。
- Nacos 2.x，`target/nacos-server.jar`。依次检查 `DEMO_NACOS_HOME`、`%LOCALAPPDATA%\Programs\nacos`、`C:\nacos`、仓库内 `nacos`，不依赖 `startup.cmd`。
- Node.js 22.12+ 或24，已安装的 `src/web/node_modules`。直接调用本地 Vite，不依赖全局 pnpm。
- 六个已打包 JAR：`src/<服务>/target/*.jar`。入口启动现有产物，不自动拉代码、不联网安装依赖，也不自动覆盖构建结果。

缺少 JAR 时需先用 JDK 17 在 `src` 下运行 `mvn -B package`；前端依赖缺失时在 `src/web` 下用 `pnpm install --frozen-lockfile` 安装。新克隆的仓库不包含 JAR、node_modules、MySQL 数据或 Nacos，这个入口不等于免依赖安装包。

## 演示账号（拉下来就能登录）

新克隆的仓库不带数据库。`mall_user` 库里没有任何账号，按下面的顺序做一次即可（顺序不能颠倒：表是服务启动时按 `schema.sql` 建的，表不存在时种子脚本会报错）：

1. 在仓库根目录运行 `mysql --host=127.0.0.1 --port=3306 --user=root -p --execute "source src/docker/init-db.sql"`。[通用建库脚本](../src/docker/init-db.sql)只创建五个库，不修改用户或权限。[Docker 授权脚本](../src/docker/init-db-docker-grants.sql)仅在 Compose 新数据卷首次初始化时运行，本机不需要执行。
2. 启动一次服务，等 `user-service` 就绪（首次启动自动建表）
3. 执行种子脚本：

```powershell
mysql --host=127.0.0.1 --port=3306 --user=root -p mall_user --execute "source src/docker/seed-demo-accounts.sql"
```

| 账号 | 口令 | 身份 | 能演示什么 |
| --- | --- | --- | --- |
| `demo_buyer` | `Demo12345` | 买家 | 下单、购物车、评价、售后退款 |
| `demo_buyer2` | `Demo12345` | 买家 | 跨店结算、秒杀限购等需要两个买家的场景 |
| `demo_seller` | `Demo12345` | 卖家 | 店铺已审核通过、营业中、保证金已登记，可直接发布商品 |
| `demo_seller2` | `Demo12345` | 卖家 | 第二家店，用于跨店合并结算 |
| `demo_admin` | `Demo12345` | 管理员 | 账号与商品审核、售后仲裁、结算与对账 |

脚本可重复执行，只会把演示账号和演示店铺重置回固定状态，不新增重复行，也不动其它账号。五个账号共用一个公开的演示口令，**只能用于本地演示**；任何真实部署都要删掉这份脚本或改掉口令。种子文件是 [seed-demo-accounts.sql](../src/docker/seed-demo-accounts.sql)。

口令用 BCrypt 存储，脚本里是哈希而不是明文。要换口令时不必手改哈希：设一个同名账号的 `password_hash` 为你自己的 BCrypt 值即可，或者直接改口令后重新生成哈希替换脚本中的值。

## 旧库升级

**新库不需要执行迁移**；按上文建库后，各服务首次启动会建表。沿用旧数据库时，先升级再启动新版，否则订单或售后列表可能因缺列返回 500。启动器不会自动执行迁移。

1. 停止商城应用，保留 MySQL。备份并核验 `mall_user`、`mall_product`、`mall_order` 和 `mall_payment`，备份只存本地。脚本适用于已有商城基表的 MySQL 8，不用于初始化空库。
2. 在仓库根目录运行[统一迁移脚本](../scripts/migrate-local-db.ps1)，确认停服与备份后输入 `YES`，再隐藏输入本机 MySQL 口令。默认连接 `127.0.0.1:3306`，可传 `-Port`、`-User`；账号需要对目标库执行迁移所需的权限。

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/migrate-local-db.ps1
   ```

3. 看到 18 个脚本与 5 项 SQL 校验通过后，再启动新版，登录买家验证「我的订单」和「我的售后」。脚本不删业务数据，会回填缺失的历史发货和完成时间。MySQL DDL 不能整体回滚；遇到异常立即停止并核对备份，不清库、不跳过报错。

## 脚本的边界

- 仅本机演示；前端只监听 `127.0.0.1:5173`，不开放局域网或公网。
- 不修改用户／系统 `JAVA_HOME`、PATH、注册表、防火墙、数据库权限。
- 不保存数据库密码，不把它放在命令行参数中；只临时传给需要的业务子进程，随后恢复父进程环境。不会写 `.env`。
- JWT签名密钥和内部调用令牌默认各自随机生成，使用Windows当前用户DPAPI加密保存于被忽略的`.run/demo-jwt-secret.xml`和`.run/demo-internal-token.xml`；数据库密码仍不保存。若自行设置`JWT_SECRET`或`INTERNAL_TOKEN`，至少32字符并全栈一致，切勿打印或提交。加密文件仅同一Windows用户/机器可使用。公开的旧开发JWT默认值已弃用。
- 新版后端仅监听127.0.0.1，并向Nacos注册该地址；服务入口除健康探针外都要求内部令牌。浏览器不持有内部令牌，由网关在清除外来身份头后注入，Feign调用也携带。库存/订单内部状态操作不经用户网关公开。
- 第一次升级需要重新打包六个JAR；启动器检查安全版本标记，不启动旧产物。发现旧版或令牌不一致的已运行服务会停止启动流程并提示用户自行关闭商城后端，不会强杀。重新登录会获得新随机密钥签发的JWT，旧JWT不适用于新部署。
- 启动子进程前清除 `ADMIN_BOOTSTRAP_ACCOUNT/PASSWORD`，不会意外创建或恢复管理员。
- 不结束任何既有进程。遇到端口被其他项目占用，显示端口和 PID 并停止，交给用户处理。
- 日志每次保存在独立 `logs/demo-<时间>-<PID>/`，不覆盖此前运行记录；进程归属记录在 `.run/demo-processes.json`，二者都在 `.gitignore` 中。
- 应用本身仍会按原配置执行建表/基础数据初始化；启动器不额外执行迁移或重置数据。旧库升级参见本页[旧库升级](#旧库升级)，启动器不自动替用户执行 DDL。
- 该入口不修复应用本身的已知功能与安全问题，也不代表生产部署验收。

## 成功判据

不是“端口开了就成功”。入口依次确认：

1. Nacos 服务列表 API 可用。
2. 每个后端 `/actuator/health` 返回 `UP`。
3. 网关 `/api/products` 返回业务 `code=0`。
4. 前端首页 HTTP 200，且前端代理 `/api/products` 返回 `code=0`。
5. Nacos 列表含六个服务。
6. 最后才调用系统默认浏览器打开演示页面。

默认每个组件最多等待150秒；启动失败不强制终止其他服务，保留诊断日志。修正后再次双击，可复用已起来的组件。

## 辅助检查与测试

不启动进程、不询问密码的依赖检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\src\scripts\demo.ps1 -CheckOnly
```

自动化运行时可使用 `-NonInteractive -NoBrowser`；缺少进程级 `DB_PASSWORD` 就明确失败，不读取终端输入。此模式不得将口令硬编码在脚本或提交中。

组件行为测试（不访问业务数据库、不启动商城服务）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\src\scripts\tests\demo-launcher.tests.ps1
```

原来的 `src/scripts/dev.bat` 仍保留给旧开发流程使用，但它没有前端管理，且 `stop` 按端口找进程。不要把它当本入口的安全停止器使用。本入口没有“按端口全部杀掉”的自动停止操作。

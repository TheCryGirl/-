## 3. K-02 样式与依赖接入（底座余下 0.5–1.5 日）

- Element Plus 具体版本安装后锁定，检查与当前 Vue/Vite 的实际 build，不写“绝无兼容风险”。首轮优先简单可靠的接入方式，按需优化须测量后再做。
- 在公共目录的临时演示页/组件验证，不抢别人业务页面作样板；若需要挂路由，先登记为临时入口并在交付前移除。
- 测试按钮、输入、数字输入、表格、分页、弹窗、确认、上传控件样式与键盘。
- 采用总纲的 Tailwind reset 候选，必须检查原生元素回归；`source(none)` 不用于关闭 preflight。
- 统一字体、间距、主色、危险色、状态标签映射和内容最大宽度。未知业务状态保留文本回退。
- ConfigProvider 放在正确的应用组件层处理中文文案；不要把组件误当 app.use 插件。

放行门槛 G1：开发与生产构建均正常；无整页溢出；鼠标/键盘能打开关闭弹窗；原生商品卡片不因取消 reset 失真；公共合同有一个可复制示例。

## 4. K-03 最小共享合同与公共三文件

### 确认与分页
- 确认返回 boolean，取消/关闭 false；示例必须 `if (!(await confirmAction(...))) return`。禁止取消后仍执行删除。
- 分页需要时再抽。页码和 size 分开双向绑定；切换 size 只触发一轮查询，父页面负责与原 API 对接。
- 不提前创建空壳 UiForm/UiDialog；直接统一 el-form/el-dialog 的规则和尺寸即可。
- 失败消息读取按现有业务响应及 Axios 错误结构，不用一个不适用的 `res.message` 公式替换所有页面。

### App
- 保留原路由渲染和 `auth:expired` 处理；401 后内存登录态、存储和路由表现一致。
- 不新增权限规则，不将未登录用户误判为某角色。

### AppHeader
- 保持导航目的地、角色判断、退出行为；窄屏能展开和关闭菜单。
- 对已有重复导航/入口问题先登记，不把路由修复夹进样式提交。
- 购物车或身份更新依赖现有事件，不让页面负责人修改 Header。

### ProductCard
- 保持父页面传入的商品结构和 `click(product)` 事件。
- 金额仍以分转元，图片尺寸/回退、标题截断和可点击区域一致。
- 来财的商品列表、fd 的收藏/历史可能依赖此组件；合同变化先通知三人（含商品详情 yy 的跳转对接），不独自改事件名。

交付：公共组件 PR 小步合并；新 props 只做兼容扩展，不能中途让页面全部返工。

## 6. K-05 最终验收（1–2 日）

| 场景 | 操作与期望 |
|---|---|
| 买家主链 | 新账号登录→浏览商品→选SKU加购→选地址→下单→创建MOCK支付→支付后详情；每一步ID/金额/状态正确，无重复请求 |
| 卖家与审核 | 建商品→管理员审核→商品公开可见；修改商品后的既有审核状态行为不变 |
| 履约 | 买家已支付订单→卖家填写物流→买家按现有入口确认收货/评价；按钮随真实状态变化 |
| 售后 | 买家申请→卖家处理→买家查看；仅退款/退货退款分别按原状态链测试，不增加新状态 |
| 权限与异常 | 三角色误访问、token失效、业务失败、断网、慢请求；不出现假成功，不把失败显示成空列表 |
| 并行接口 | Header认证联动、ProductCard点击、公共确认取消；整合后不能出现事件签名不一致 |
| 展示 | 360/768/1440/1920宽度抽检、Tab/Enter/Esc、长标题/大金额/空图片/空列表 |

构建与后端测试分开记录实际退出码、日志、报告。125是历史基线提示，不是要求通过修改测试数量凑数。需要浏览器自动化时先确认工具与依赖，再由你建共享配置；未运行就写未运行。

证据必须脱敏，禁止上传 JWT、密码、完整HAR。每位成员只交自己的证据，你维护总表和实验三截图。最终PR通过标准：所有阻塞缺陷关闭、无跨owner文件、构建成功、关键链路有可复现步骤和结果；遗留后端问题另列，不宣称项目无bug。

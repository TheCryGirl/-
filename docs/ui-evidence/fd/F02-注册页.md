# F02 注册页 Element Plus 改造

- 任务：F02 Register，见 [fd 任务书](../../ui-plan/fd.md)
- 分支：`feature/ui-fd-login`（基于 main `877e6e8`，在 F01 提交 `8ac10a3` 之后，**未合并、未推送**）
- 改动文件：仅 `src/web/src/views/Register.vue`；证据目录为本目录

## 实现要点

| 项 | 实现 |
| --- | --- |
| 表单 | `el-card` + `el-form`（label 在上），`sm:grid-cols-2` 两列；每个 `el-form-item` 的 `for` 指向对应输入框 |
| 字段 | 保留账号、昵称、密码、确认密码、手机号五个原字段与原 placeholder，未新增密码强度、角色等字段 |
| 校验 | 原规则与文案逐条保留，校验结果按字段显示在 `el-form-item` 下方；非法输入不调用 API |
| 密码可见 | 密码与确认密码均使用 `show-password`，只切换输入框类型，不改绑定值 |
| 提交 | 按钮 `:loading` + 提交中守卫；Enter（输入框 keyup）与按钮共用 `submit` |
| 错误 | HTTP 200 但业务码非 0 时用 `el-alert` 展示后端 `message`（原实现会误报成功，本次修正）；HTTP/网络异常走 catch |
| 成功 | 显示「注册成功，正在跳转到登录页…」，保留 900ms 后跳转 `login` |
| testid | `register-account`、`register-nickname`、`register-password`、`register-confirm`、`register-phone`、`register-error`、`register-success`、`register-submit` |
| 未改 | API、store、router、公共组件、依赖与锁文件、其他页面 |

## 验证记录

本地使用临时 mock 网关（仓库外）模拟统一响应 `{ code, message, data }`，仅用于开发验证。

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 生产构建 | `pnpm run build` | 通过（vite 8.3.4，971ms） |
| 初始渲染 | 打开 `/register` | 5 个字段渲染正常，label 的 `for` 与 input id 全部对应，4 个必填项带星号；控制台无告警；见 [1440 截图](images/f02-register.png)、[360 截图](images/f02-register-360.png) |
| 空提交 | 不填直接点「注册」 | 显示「请填写账号」「请填写昵称」「密码须为 6-32 位」，无注册 XHR |
| 非法格式 | 账号 `ab`、昵称 `a`、密码 `123`、确认 `456`、手机 `123` | 5 条原文案全部按字段显示，无 XHR |
| 边界值 | 账号 21 位、昵称 21 位、密码 33 位、手机 `12345678901` | 对应字段报错，无 XHR；确认密码一致时不报错 |
| 成功 | 20 位账号、20 位昵称、32 位密码、合法手机号 | 显示成功提示，唯一一次 `POST /api/users/register`，约 900ms 后跳转 `/login` |
| 重复点击 | 提交期间连续点击两次 | 按钮 `is-loading`、禁用、文案「提交中…」，网络仅 1 次请求 |
| 业务失败 | 使用已存在账号 `admin` 注册（mock 返回 code 10002） | 页面显示「账号已存在」，不显示成功、不跳转 |
| Enter 提交 | 在账号框触发 `keyup(Enter)` | 走同一 `submit`，发出 1 次注册请求并成功跳转 |
| 密码可见 | 点击密码框可见按钮 | `type` 在 `password`/`text` 间切换，输入值不变；确认密码同样支持 |
| 响应式 | 360/768/1920 宽 iframe 实测 | 单列/双列切换正常，主内容无横向溢出（768、1920 下 `scrollWidth` 分别 768、1920） |

## 未测与风险

## 二、统一改造约定

| 项 | 做法 |
| --- | --- |
| Element Plus | 模板直接写 `<el-*>`，由 unplugin 按需引入；**没有** `import ... from 'element-plus'` |
| 读接口 | `isOk(data)` 判断业务成功，`unwrapResult(data)` 取数据；列表读 `data.list` / `data.total` |
| 写接口 | 一律 `isOk(data)`；`Result<Void>` 的 `data=null` 视为成功 |
| 二次确认 | 删除购物车条目、删除地址、取消订单、确认收货、评价取消等使用 `confirmAction`；取消立即 `return`，不发请求 |
| 金额 | 后端分为单位，页面用 `utils/format.js#formatPrice` 除 100；元→分只在上送前 `Math.round(Number(v) * 100)` |
| 状态文案 | 订单状态取 `constants/status.js`（`PAID` 统一显示「待发货」）；售后类型/状态取 `utils/afterSale.js`（覆盖 `EXCHANGE` / `COMPLETED`） |
| 总量文案 | `formatTotal`：ProductList / OrderList 有分页，只显示总量；AfterSales 固定前 50 条且无分页，传 `list.length` 如实标注可见范围 |
| 三态 | 每页加载、空、失败分开；失败显示 `el-result` + 重试，绝不复用空态文案 |
| 防重 | 提交/审核/物流等按钮使用局部 `loading` + 入口 `return`；成功后刷新，失败保留输入 |
| 标识 | 行内 `data-testid` 使用 `productId` / `skuId` / `cartItemId` / `orderId` / `paymentId` / `addressId` / `ticketId`，不用数组下标 |

## 三、逐页改造与「必须保留」核对

### L01 商品列表

- 筛选区改为 `el-input` / `el-select`，关键词保留 400ms 防抖；分类、排序、价格、页码继续同步到地址栏，刷新与分享链接可还原。
- 价格输入仍以「元」展示，提交前转分；最低价高于最高价、负数、非数字仍在本地拦截。
- 商品网格继续使用 `ProductCard`（未改动公共组件），点击仍跳 `product-detail`。
- 分页改用 `el-pagination`，页码仍从 1 开始；总量只显示「共 N 件」，避免第二页出现「当前显示前 2 件」的误导。
- 空态保留「当前筛选：…」与「清空筛选条件」；失败态与空态分离，可重试。
- 键盘：从关键词输入框 Tab 可到「查询」按钮，回车触发筛选（截图 `L01-keyboard-focus.png`）；8 页均补了 scoped `.el-button:focus-visible` 焦点环（Element Plus 默认不显示，基础层未统一处理）。

**保留**：`GET /api/products` 的 `page` / `size` / `sort` / `keyword` / `categoryId` / `minPrice` / `maxPrice`（分）参数、`ProductCard` 的 props 与点击事件、URL 查询语义。

### L02 购物车

- 勾选改为 `el-checkbox`，调用 `PUT /cart/items/{cartItemId}/select`，请求体仍是 `{ selected: boolean }`；失败重新拉取购物车，避免金额假更新。
- 数量改为 `el-input-number`，保留 1 ~ min(999, 库存) 约束；成功后才更新本地数量与小计。
- 删除前 `confirmAction`，取消不发请求；确认后只发一次 `DELETE`，成功移除行。
- 失效商品仍置灰、禁止勾选、标注下架原因，且不参与已选合计。
- 结算仍把选中条目写入 `sessionStorage.checkoutItems`，并跳 `order-confirm`。
- 三种 ID 全程未混用：勾选/数量/删除用 `cartItemId`，结算请求体只带 `cartItemIds`，商品与规格分别保留 `productId` / `skuId`。

**保留**：`GET /cart`、`PUT /cart/items/{id}`、`PUT /cart/items/{id}/select`、`DELETE /cart/items/{id}` 的方法、路径、字段与类型。

### L03 确认订单

- 地址改为 `el-radio-group`，整块可点；仍优先选中默认地址，无默认时退回第一条。
- 商品清单、件数、应付合计全部由后端分值计算；金额不由组件格式化字符串倒算。
- 提交仍只带 `{ addressId, cartItemIds }`，每次尝试生成一个 `Idempotency-Key`；保留原幂等键生成规则。
- 提交按钮 `loading` + 入口防重；业务失败/网络失败保留页面与输入，不跳转。
- 无地址时保留「去个人中心添加」入口；无结算条目或地址加载失败显示错误态与「返回购物车」。
- 窄屏地址文本允许换行（`el-radio__label` 取消 nowrap），375px 下不截断。

**保留**：`POST /api/orders` 的 `addressId` / `cartItemIds`、幂等头、地址结构与默认地址判断（`defaultAddress ?? isDefault`）。

### L04 支付订单

- 只保留 MOCK：页面明确提示「当前仅支持 MOCK 模拟支付」，没有支付渠道选择、没有倒计时。
- 创建支付单：`POST /api/payments`，请求体仍为 `{ orderId, channel: 'MOCK' }`，带 `Idempotency-Key`。
- 模拟支付：`POST /api/payments/mock/pay`，仍传 `{ paymentId }`，不是 `payNo`、不是 `orderId`。
- 未创建支付单时后端 `code=60001` 只作为业务错误处理，不把错误包装成支付单。
- 订单状态统一取 `constants/status.js`，`PAID` 显示「待发货」；支付单状态使用 `PAYMENT_STATUS_MAP`。
- 成功后刷新订单并 1.5 秒跳订单详情；离开页面时清理跳转定时器。
- 创建失败/支付失败只提示后端 message，按钮恢复可重试，不显示假成功。

**保留**：`GET /orders/{id}`、`GET /payments/order/{orderId}`、`POST /payments`、`POST /payments/mock/pay` 的方法、路径、字段与跳转逻辑。

### L05 订单列表

- 保留订单卡片与点击进详情；卡片增加 `tabindex` / Enter 键盘进入。
- 角色切换（买家/卖家）与状态筛选仍走原参数；状态值未新增，文案统一从 `constants/status.js` 取。
- 分页改用 `el-pagination`，`page` 从 1 开始；总量只显示「共 N 单」，避免分页时误导。
- 加载/空/失败三态分离；筛选无结果时提供「查看全部订单」，失败可重试。
- 订单号、状态、件数、下单时间、实付金额均保留；金额除 100。

**保留**：`GET /api/orders` 的 `role` / `page` / `size` / `status`、详情跳转 `orderId`、状态可操作条件（本页只做展示与跳转，不改状态）。

### L06 订单详情

- 订单信息、收货地址、商品信息、金额分组展示；状态标签统一取 `constants/status.js`。
- 取消订单、确认收货改为 `confirmAction`；取消确认框返回 false 时立即 return，不发请求；成功后重新加载详情。
- 评价入口条件不变：`BUYER` + `COMPLETED` + 尚无评价；一单一评仍由后端兜底。
- 评价表单迁移到 `el-dialog`：`el-rate`、`el-input type=textarea`、`el-checkbox`、`el-button`；取消关闭保留草稿，成功后清空草稿并刷新评价。
- 上传保留原有流程：隐藏原生 file input + `FormData('file')` → `POST /api/products/images`，不引入 `el-upload` 的默认 action，实测一次选择只发一次请求；最多 3 张、单张 5MB、返回 `{ url }` 解析均不变；大图不发请求。
- 「申请售后」仍跳 `/after-sales?orderId=...`，条件仍是 `BUYER` + `PAID/SHIPPED/COMPLETED`；未新增订单状态或售后流程。

**保留**：`GET /orders/{id}`、`PUT /orders/{id}/cancel`、`PUT /orders/{id}/confirm`、`GET/POST /orders/{id}/evaluations`、`POST /products/images` 的方法、路径、字段与条件。

### L07 个人中心

- 个人资料改为 `el-form`；昵称最长 20、手机号最长 11，字段与保存接口不变；保存成功同步 `setUser`，Header 仍通过原登录态机制更新。
- 头像保留原上传：隐藏原生 file input + `FormData('file')` → `POST /api/users/avatar`，5MB 限制、`{ avatar }` 解析与失败重试不变；上传后重新拉取个人信息，保证库与内存一致。
- 头像仍支持直接填写图片地址与「移除」；移除只清空草稿，保存后才写库。
- 地址弹窗使用 `el-form` 规则：收货人、手机号、省份、城市、详细地址必填，手机号 `^1[3-9]\d{9}$`，区/县选填；规则与原页面一致，未新增业务限制。
- 地址新增/编辑/删除/设为默认仍走原接口；删除使用 `confirmAction`，取消不发请求；默认地址切换后重新拉取列表。
- 地址加载失败只显示错误与重试，不显示「还没有收货地址」。

**保留**：`GET/PUT /users/me`、`POST /users/avatar`、`GET /users/{userId}/addresses`、`POST/PUT/DELETE /users/addresses...`、`PUT .../default` 的方法、路径、字段与校验语义。

### L08 我的售后

- 申请类型仍为仅退款 / 退货退款 / 换货（含 `EXCHANGE`），金额仍按元输入、提交转分；`EXCHANGE` 不传金额。
- 剩余可退金额、支付成功状态、订单 `PAID/SHIPPED/COMPLETED` 条件保持不变；无可退金额时提示并禁用提交。
- 提交仍带 `Idempotency-Key`；后端拒绝只提示 message，不显示成功；成功后刷新订单与售后记录。
- 售后记录按状态筛选，步骤使用 `el-steps`（按类型展示 3/4 步），驳回显示原因；退货物流单号仍只对 `APPROVED` 且非仅退款的售后单开放，提交后状态由后端刷新。
- 列表保持 `page=1&size=50`；使用 `formatTotal(total, '单', tickets.length)` 如实标注只显示前 50 条。
- 加载/空/失败三态分离；筛选无结果显示空态并可「查看全部记录」。
- 页面没有新增任何图片上传入口。

**保留**：`POST /payments/after-sales`、`GET /payments/after-sales`、`PUT /payments/after-sales/{ticketId}/return-shipment` 的方法、路径、字段与状态条件。

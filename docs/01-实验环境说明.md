# 实验环境说明

本文说明本项目实际采用的工具链，对照《软件工程实验》指导书「二、实验环境」逐项落实，并记录选型理由。

## 一、建模工具

**选型：PlantUML 1.2024.7**

指导书要求 StarUML、Rational Rose 或 PlantUML 等 UML 建模工具。本项目选用 PlantUML，理由有三：

1. **源文件可纳入版本控制**。`.puml` 是纯文本，每次改动都能在 Git 里看到具体 diff，配合指导书「必须有清晰的 Commit 记录」的要求，建模过程本身就是可追溯的。StarUML、Rational Rose 产出的是二进制工程文件，diff 无意义。
2. **可重复生成**。图与源文件严格对应，改一处重新渲染即可，不会出现「图改了但忘记保存」的情况。
3. **适合协作**。文本文件合并冲突可读、可手工处理，多人同时改不同用例图不会损坏文件。

运行环境：Java 24（`C:\Program Files\Java\jdk-24`）+ 离线 `plantuml.jar`，无需联网。

渲染脚本见 `design/scripts/render_uml.py`：因 PlantUML 在含中文的路径下会静默不输出，脚本先复制到纯 ASCII 临时目录渲染，再拷回 `design/images/`。

## 三、开发工具

### 前端

**选型：Vue.js 3 + Vue Router + Vite + Tailwind CSS**

指导书鼓励使用 Vue.js / React / Angular 任一现代框架。选 Vue 3 的理由：

- 中文资料与社区最完整，团队上手成本低；
- 组件化后，购物车、订单项、商品卡片这类重复结构只需写一次；
- 数据驱动视图，订单状态与金额联动变化时不必手工操作 DOM；
- Vite 构建产物为本地静态文件，不依赖外网 CDN，部署到云服务器后离线也能正常显示。

> 补充说明：项目初期参考了既有的校园二手交易平台原型（`src/campusEasy/`），其前端为单文件 HTML + Tailwind CDN。CDN 版本仅适合开发预览，官方不建议用于生产，且断网时样式完全失效。因此前端重写为 Vue 3 工程（`src/web/`），彻底摆脱对外网的依赖。

依赖版本：`vue ^3.5.42`、`vue-router ^5.4.0`、`vite ^8.3.0`、`tailwindcss ^4.3.3`、`axios ^1.20.0`，包管理器 pnpm 11.21。

### 后端

**选型：Spring Boot 3.2 + Java 17 + MyBatis 3.5**

指导书列出的四个后端选项中，Spring Boot 与云原生微服务选题最匹配：

- 与 Spring Cloud Alibaba（Nacos 注册与配置中心）、Spring Cloud Gateway 同属一个生态，服务治理开箱可用；
- 社区成熟，分布式事务、限流熔断、链路追踪都有现成组件；
- 既有参考原型 `campusEasy` 本身即 Spring Boot 3.2 + MyBatis，业务代码可复用，把精力集中在微服务拆分上。

### 数据库

**选型：MySQL 8.0**

指导书可选 MySQL 或 MongoDB。选 MySQL 的决定性原因在本项目的核心设计上：

- 库存预占依赖**行级锁与条件 UPDATE**（`UPDATE sku SET stock_locked = stock_locked + ? WHERE sku_id = ? AND stock_available >= ?`），MySQL 的原生支持直接可用；
- 支付回调幂等依赖 **`UNIQUE(tradeNo)` 唯一约束**做去重，这是关系型数据库的强项；
- 订单状态机、金额计算需要**事务保证**，MongoDB 的多文档事务在实现与运维上都更复杂。

MongoDB 更适合文档形态的商品详情、日志类数据，与本项目的核心一致性诉求不匹配。

**辅助存储：Redis 7（原定选型）**，用于会话令牌、下单幂等令牌与热点数据缓存。

> **2026-10-27 现状注记**：Redis **实际未落地**。当前实现用数据库唯一键做幂等、用条件 UPDATE 做并发控制、
> 用 `order.compensation` 表 + 定时任务做补偿，运行不依赖 Redis。选型决策本身保留在此，
> Docker Compose 里的 redis 服务属后续规划，没有任何微服务依赖它。

## 四、部署

**选型：Docker Compose（本地）→ 云服务器试用套餐（验收）**

指导书鼓励使用 Docker 容器化部署。本项目分两阶段：

1. **开发与联调阶段**：本地直接启动 Nacos + MySQL + 五个微服务（当前未用 Redis）；Docker Compose 编排属未验收的规划；
2. **验收阶段**：短期租用云服务器试用套餐，做一次真实环境部署，验证容器化产物在公网可用。

规模说明：五个微服务各占一个容器，基础设施各占一个容器，单机 4 GB 内存即可跑通全部服务。

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| **JDK** | **17（LTS）** | Spring Boot 编译目标。**不要用 21/23/24**，原因见 6.2 |
| Maven | 3.9.x | 构建工具 |
| MySQL | 8.0 | 字符集 utf8mb4 |

### 6.2 为什么锁 JDK 17

本项目第一次代码合并后出现过「两位成员提交的代码在我这里全部编译失败」的情况。排查结论：

**JDK 23 起 javac 默认关闭隐式注解处理（`-proc:none`）**。Lombok 依赖「从 classpath 自动发现注解处理器」这个机制，在新 JDK 下处理器根本不会运行，`@Data` / `@Builder` 生成的 getter、setter、builder 全部消失，编译报「找不到符号 `builder()`」。

具体版本兼容线：

| 组件 | 出问题的版本 | 可用版本 |
| --- | --- | --- |
| Lombok | 1.18.32（Spring Boot 3.2.5 默认），不支持 JDK 24 | 1.18.46+ 支持 JDK 24 |
| Mockito | 5.7（Spring Boot 3.2.5 默认），不支持 JDK 24 | 5.14+ 支持 JDK 24 |

即便升级到可用版本，也还要在 `maven-compiler-plugin` 里显式写 `annotationProcessorPaths` 与 `-proc:full` 才行，属于额外折腾。

**结论：统一用 JDK 17，不要升 21+。** 这是 LTS 版本，也是 Spring Boot 3.2 官方支持的主版本。

如果你本机装了多个 JDK，每个服务的目录下可以用环境变量指定：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17"
mvn -v      # 确认输出里是 Java 17
```

## 一、为什么换 Element Plus

当前前端 31 个 `.vue` 文件、6543 行，**全部手写原生 HTML + Tailwind class**，没有任何组件库。

实测发现管理端 10 个页面里 **7 个含表格**（`AdminUsers`、`AdminShops`、`AdminAuditLogs`、`AdminEvaluations`、`AdminFinance`、`AdminRefunds`、`AdminRisk`），结构与交互高度重复——都是「筛选栏 + 表格 + 分页 + 弹窗」。手写这套样板是纯体力活，换组件库反而更省工。

选型对比：

| 候选 | 结论 | 原因 |
| --- | --- | --- |
| **Element Plus** | **采用** | Vue 3 原生，官方支持 Vite；表格/表单/弹窗/上传/日期/树组件齐全；中文文档最全；支持按需引入 |
| Naive UI | 备选 | 与 Tailwind 共存最干净（CSS-in-JS），但组件级样式不易覆盖，团队上手成本高 |
| Ant Design Vue | 否 | 版本迭代慢，Vue 3 适配层较老 |
| Vuetify | 否 | Material 设计语言重，体积大 |
| 继续手写 Tailwind | 否 | 管理端重复劳动量大于迁移成本 |

> 这条选型是本项目的技术决策，后续页面统一按此执行。

### 4.2 Tailwind preflight 冲突处理（一次性解决）

Element Plus 引入后**必须先于** `style.css`，且 Tailwind 的 preflight 会重置 `el-button`/`el-input`/`el-table` 的边框与背景，典型表现是「表格没边框、按钮透明」。

`main.js` 顺序：

```js
import 'element-plus/dist/index.css'
import './style.css'
```

`style.css` 改为限定扫描范围：

```css
@import 'tailwindcss' source(none);
@source '../src/**/*.{vue,js}';
```

这一步由哭女一次性验证通过（用 3 个页面交叉验证），**其他人不得各自处理**，否则风格必然分裂。

## 六、全组统一约定（必须遵守）

### 6.1 修改范围

- **允许**：`<template>`、`<style>`、组件事件绑定、`import` 组件库
- **禁止**：改动 `src/api/index.js`、`src/stores/auth.js`、路由守卫逻辑

> 理由：后端 121 个用例与 14 项 E2E 依赖现有接口契约，改请求封装会连带出问题。

### 6.2 组件使用

| 场景 | 统一做法 |
| --- | --- |
| 表格 | 一律用 `UiTable`，**不直写 `el-table`** |
| 分页 | 一律用 `UiPagination` |
| 筛选栏 | `el-form` + `inline` 模式 |
| 确认框 | `UiConfirm.confirm()`，**禁用 `window.confirm` / `alert`** |
| 错误提示 | `ElMessage.error(res.message \|\| '操作失败')` |
| 空状态 | `UiEmpty` |
| 页面加载 | `UiLoading`（禁 `v-if` 兜整页） |

### 6.3 data-testid 规范

格式：`页面前缀-元素-语义`，全小写连字符。

示例：

```html
<div data-testid="admin-users-table">
<button data-testid="admin-users-create">
<!-- 行内元素带 id -->
<tr :data-testid="`admin-users-row-${row.userId}`">
```

> 保留 `data-testid` 是为了让已有的 E2E 脚本在改造后只需改选择器、不必改断言。

### 6.4 加载态三级

1. 页面级：`UiLoading` 包裹整页
2. 表格级：`<UiTable :loading="loading">`
3. 按钮级：`<el-button :loading="submitting">`

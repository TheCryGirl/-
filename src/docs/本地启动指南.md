# 本地启动指南

本文说明如何在本机把 Nacos、网关、各业务服务和前端跑起来。**不需要 Docker**，直接在本机启动即可；如果只想快速起停，可以用 [一键启停说明](一键启停说明.md) 里的 `dev.bat`。

## 一、需要先装的东西

| 工具 | 版本 | 检查命令 |
| --- | --- | --- |
| JDK | **17**（推荐，与 `pom.xml` 的 `java.version` 一致） | `java -version` |
| Maven | 3.8+ | `mvn -v` |
| Nacos | 2.3.2 | 见第 3 步 |
| MySQL | 8.x（开发环境实测 8.4.9） | `mysql --version` |
| Node.js | 18+ | `node -v` |
| pnpm | 9+ | `pnpm -v` |

> 请用 JDK 17。更高版本的 JDK 未在本项目验收，不作为可行环境；`pom.xml` 编译目标是 17，换版本前先确认 Spring Boot 3.2.5 与 Nacos 客户端表现正常。
>
> Redis 当前**不是必需项**：代码未接入 Redis，未安装也能正常启动；`docker-compose.yml` 里的 Redis 服务属后续部署规划，第 3.2 节仅作可选记录。

## 二、启动顺序

顺序不能乱，后面的依赖前面的。

```
1. MySQL    → 建五个库
2. Nacos    → 8848
3. 各微服务 → 9001~9005
4. gateway  → 9000
5. 前端     → 5173
```

## 三、逐步启动

### 3.1 MySQL：建库

```powershell
mysql -u root -p < src/docker/init-db.sql
```

或者手动执行 `src/docker/init-db.sql` 里的 SQL。建完应该有五个库：

```sql
SHOW DATABASES LIKE 'mall_%';
-- mall_user / mall_product / mall_cart / mall_order / mall_payment
```

### 3.2 Redis（可选，当前未启用）

当前所有服务都不依赖 Redis：订单一致性用 DB 幂等令牌、条件更新和 `order.compensation` 定时补偿实现，契约里的 Redis 异步队列与分布式锁尚未落地。**不装 Redis 不影响启动和功能验证。**

如后续要按部署规划验证，Windows 下可以用 Docker 跑一个：

```powershell
docker run -d --name mall-redis -p 6379:6379 redis:7-alpine
```

或者用本机装的 Redis 服务。验证：

```powershell
redis-cli ping   # 返回 PONG
```

### 3.3 Nacos

**下载**（2.3.2，约 100 MB）：

https://github.com/alibaba/nacos/releases/download/2.3.2/nacos-server-2.3.2.zip

**解压后启动**（单机模式）：

```powershell
cd nacos\bin
.\startup.cmd -m standalone
```

**验证**：浏览器打开 http://localhost:8848/nacos

默认账号密码都是 `nacos`。登录后进「服务管理 → 服务列表」，现在应该是空的。

> **注意版本**：Nacos 3.x 与 Spring Cloud Alibaba 2023.0.3.2 不兼容，必须用 2.3.x。

### 3.4 网关

```powershell
cd src/gateway
mvn spring-boot:run
```

或者打包后跑：

```powershell
mvn clean package -DskipTests
java -jar target/gateway-1.0.0-SNAPSHOT.jar
```

**验证**：

```powershell
# 健康检查
curl http://localhost:9000/actuator/health
# 期望：{"status":"UP",...}
```

同时在 Nacos 控制台的「服务列表」里应该能看到 `gateway`。

### 3.5 各微服务

服务按 `user-service → product-service → cart-service → order-service → payment-service` 的顺序启动（后面的依赖前面的）。每个服务步骤一样，启动前先设好环境变量（见第四节）：

```powershell
$env:DB_PASSWORD = "你的 MySQL 口令"
$env:JWT_SECRET  = "至少32位的随机字符串"   # 网关与 user-service 必须一致

cd src/<service-name>
mvn spring-boot:run
```

> 手动 `mvn spring-boot:run` 时 `JWT_SECRET` 必须自己设置，否则网关和 user-service 会在启动时报「JWT_SECRET 长度至少 32 位」。
>
> 不想逐个敲命令时，用 `dev.ps1 start`（或 `dev.bat start`）一键启动，脚本会按顺序拉起 Nacos、网关和五个服务，并在未设置 `JWT_SECRET` 时注入开发用密钥并提示。具体见 [一键启停说明](一键启停说明.md)。

#### 3.5.1 初始化管理员账号

注册接口只会创建 `BUYER`，管理端需要 `ADMIN`。启动 user-service 前设置两个环境变量，服务启动时会幂等地创建（或提升）该账号：

```powershell
$env:ADMIN_BOOTSTRAP_ACCOUNT = "admin"
$env:ADMIN_BOOTSTRAP_PASSWORD = "至少6位的口令"
```

- 不设置则跳过，不会写入任何默认口令
- 账号已存在但不是管理员时，会被提升为管理员
- 创建成功后建议移除这两个变量，后续用管理员账号登录，在「用户管理」里把买家设为卖家

### 3.6 前端

```powershell
cd src/web
pnpm install
pnpm dev
```

访问 http://localhost:5173

前端的 `vite.config.js` 需要把接口代理指向**网关 9000**，而不是某个具体服务：

```js
server: {
  proxy: {
    '/api':     { target: 'http://localhost:9000', changeOrigin: true },
    '/images':  { target: 'http://localhost:9000', changeOrigin: true },
  }
}
```

## 四、环境变量

口令与密钥一律从环境变量读，**不要写进代码或配置文件**。

| 变量 | 用在哪 | 说明 |
| --- | --- | --- |
| `DB_PASSWORD` | 各服务 | MySQL 口令 |
| `JWT_SECRET` | 网关、user-service | JWT 签名密钥，**必须两边一致**；无内置默认值，不设置则服务启动失败 |
| `MOCK_SECRET` | payment-service | 模拟支付签名密钥 |
| `ADMIN_BOOTSTRAP_ACCOUNT` | user-service | 初始管理员账号，不设置则跳过初始化 |
| `ADMIN_BOOTSTRAP_PASSWORD` | user-service | 初始管理员口令，至少 6 位 |
| `NACOS_ADDR` | 各服务 | 默认 `127.0.0.1:8848`，Docker 内是 `nacos:8848` |
| `PRODUCT_SERVICE_URL` | user-service | 可选：直连商品服务地址（如 `http://127.0.0.1:9002`）；不设置则按 Nacos 服务名负载均衡 |
| `INTERNAL_TOKEN` | user-service、product-service | 可选：内部接口令牌；product-service 未配置时不校验，配置后两边必须一致 |
| `USER_UPLOAD_DIR` | user-service | 可选：头像根目录，默认 `uploads`，静态访问路径为 `/avatars/**` |
| `PRODUCT_SERVICE_URL` / `USER_SERVICE_URL` / `CART_SERVICE_URL` | product-service、order-service | 可选：Feign 直连地址（如 `http://127.0.0.1:9002`）；不设置则按 Nacos 服务名负载均衡 |

PowerShell 里临时设置（`JWT_SECRET` 与 `DB_PASSWORD` 是必设的两项，其余按需）：

```powershell
$env:DB_PASSWORD = "你的口令"
$env:JWT_SECRET  = "至少32位的随机字符串"
```

**DB_PASSWORD**：各服务 `spring.application` 的 `spring.datasource.password` 从它读取（默认用户名为 `root`，可用 `DB_USER` / `DB_HOST` / `DB_PORT` 覆盖），没设置连不上库。

**JWT_SECRET**：至少 32 位，因为 JJWT 用 HMAC-SHA256 时密钥长度有下限。配置文件里不再写默认值：没设置就直接启动失败，避免弱密钥被带到线上（`dev.ps1` 一键启动时会自动注入一份开发用密钥）。

**头像与店铺相关（#49 / #51）**：头像存在 `user-service` 的 `uploads/avatars/`，静态映射 `/avatars/**`；网关新增 `user-avatars` 路由把 `/avatars/**` 原样转发。`INTERNAL_TOKEN` 不设置时为开发态（不校验内部接口），部署前建议与 `PRODUCT_SERVICE_URL` 一起配置。

## 六、常见问题

### 网关启动报 `spring-boot-starter-web` 冲突

Spring Cloud Gateway 基于 WebFlux，**不能**同时引入 `spring-boot-starter-web`（Servlet 版）。检查 pom.xml 里有没有这个依赖，有就删掉。

### 服务注册不上 Nacos

1. 检查 Nacos 是否启动：http://localhost:8848/nacos
2. 检查 `spring.cloud.nacos.discovery.server-addr` 配置
3. 看服务启动日志里有没有 `nacos registry, ... register finished`

### 网关转发报 503

说明目标服务没注册到 Nacos，或者服务名对不上。检查：
- 服务的 `spring.application.name` 是否与网关路由的 `lb://<name>` 一致
- Nacos 服务列表里有没有该服务

### JWT 校验一直失败

- 确认 `JWT_SECRET` 在网关和 user-service 里**完全一致**（包括空格）
- 确认令牌没被截断，请求头是 `Authorization: Bearer <token>`（Bearer 后有一个空格）

### 端口被占用

```powershell
netstat -ano | findstr :9000
taskkill /PID <进程号> /F
```

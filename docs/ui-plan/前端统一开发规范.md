## 三、状态规范（六种状态）

| 状态 | 用什么 | 文案 | 可重试 |
| --- | --- | --- | --- |
| 加载中 | `UiTable :loading` / 页面级 `v-loading` | — | — |
| 空数据 | `el-empty` 或 `UiTable` 的 `empty-text` | 「暂无数据」 | — |
| 请求失败 | `el-result status="error"` + 重试按钮 | `resolveErrorMessage(err)` | ✅ 是 |
| 无权限 | `el-result status="warning"` | 「无权限访问」 | ❌ 否 |
| 操作成功 | `showSuccess('xx成功')` | 具体动作 | — |
| 操作失败 | `showError(resolveErrorMessage(err))` | 后端 message | — |

### 3.1 失败态代码（复制用）

```vue
<el-result v-if="loadError" status="error" :sub-title="loadError">
  <template #extra>
    <el-button type="primary" @click="fetchList">重试</el-button>
  </template>
</el-result>
<UiTable v-else ... />
```

**关键**：失败和空数据必须分开。**接口报错不能显示成「暂无数据」**。

## 四、接口调用规范

### 4.1 成功判断（**最易错，必看**）

```js
// 读接口：取数据
const { data } = await productApi.list(params)
if (!isOk(data)) {
  loadError.value = data?.message || '加载失败'
  return
}
const payload = unwrapResult(data)
list.value = payload?.list ?? []
total.value = payload?.total ?? 0
```

```js
// 写接口：只看成功与否
const { data } = await productApi.audit(id, { approved: true })
if (!isOk(data)) {
  showError(data?.message || '操作失败')
  return
}
showSuccess('审核通过')
```

> ⚠️ `Result<Void>` 的 `code=0, data=null` **是成功**。用 `unwrapResult` 判断有无数据会把成功当失败。

### 4.2 异常处理

```js
try {
  loading.value = true
  // ...
} catch (err) {
  showError(resolveErrorMessage(err, '加载失败'))
} finally {
  loading.value = false   // finally 必写
}
```

**错误文案一律走 `resolveErrorMessage`**，禁止硬编码后端 code。

### 4.3 防重复提交

```js
async function handleSubmit() {
  if (submitting.value) return   // 进入先 return
  submitting.value = true
  try {
    // ...
  } finally {
    submitting.value = false
  }
}
```

按钮：`:loading="submitting"`

### 4.4 分页与筛选

- 用 `usePagination`，page 从 **1** 开始
- 筛选条件变化时 **page 重置为 1**
- 空字符串**不传参**（不要传 `keyword=`）

## 六、交互规范

### 6.1 必用 `confirmAction` 的场景

- 删除（用户、商品、地址、购物车条目、收藏、历史、评价）
- 上下架 / 停用 / 冻结
- 取消订单
- 退出登录
- 清空购物车 / 清空历史
- 修改角色权限
- 审核通过 / 驳回

### 6.2 其他

- 按钮 loading：`submitting` 粒度，作用在**触发动作的那个按钮**上
- 表单校验：`trigger: 'blur'` / `'change'`，提交前调 `validate()`
- 成功后：新增/编辑 → 关闭弹窗 + 刷新列表；删除 → 刷新列表（用 `afterDelete`）

## 七、代码风格

### 7.1 `<script setup>` 顺序

```js
// 1. import
// 2. props / emits
// 3. 响应式状态 ref/reactive
// 4. computed
// 5. 方法
// 6. 生命周期
```

### 7.2 命名

- 组件：`PascalCase`
- 变量/函数：`camelCase`
- 事件处理：`handleXxx`
- 布尔值：`is/has/can` 开头

### 7.3 注释

**只写「为什么」，不写「是什么」**。

- ✅ `// 后端 code=0 且 data 为 null 也是成功，必须用 isOk 判断`
- ❌ `// 设置 loading 为 true`

### 7.4 抽组件阈值

**跨 3 个及以上页面重复才抽**。只在一两处用就别抽，直接写。

## 十、常见错误清单（每条给 grep 判断方法）

| # | 错误 | 判断方法 |
| --- | --- | --- |
| 1 | 用 `unwrapResult` 判断写操作成功 | `grep -n "unwrapResult" 你的文件`，写操作里出现就是错 |
| 2 | 金额没除 100 | `grep -n "\.price" 你的文件`，看有没有 `/100` |
| 3 | 失败显示成空列表 | 检查 catch 分支有没有设置 `loadError` |
| 4 | 用 `window.confirm` | `grep -n "window.confirm" -r src/` |
| 5 | 直接 import ElMessage | `grep -n "from 'element-plus'" src/views/` |
| 6 | 改了禁改文件 | `git diff --name-only \| grep -E "api/\|stores/\|router/"` |
| 7 | 分页从 0 开始 | 看 `page = ref(0)` |
| 8 | 换每页条数没重置页码 | 看 `onSizeChange` 里有没有 `page = 1` |
| 9 | 状态直接显示原值 | `grep -n "\.status }}\|\.status}}"` 看有没有走映射 |
| 10 | 没写 `finally` 恢复 loading | `grep -n "loading.value = false"` 检查是否在 finally 里 |

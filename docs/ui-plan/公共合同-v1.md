## 二、Tailwind 与 Element Plus 共存（已解决，禁止各自处理）

`src/style.css` 已改成显式分层导入，**跳过 preflight**：

```css
@layer theme, base, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
```

原因：preflight 会把 `button/input` 的 `border-style` 重置为 `solid`、背景置为 `transparent`，直接破坏 `el-button` / `el-input` / `el-table` 的外观。

**所有 base 规则用 `:where()` 包裹**：Element Plus 的样式是**未分层**的，未分层样式优先级高于任何 `@layer` 内的规则。如果不加 `:where()`，写在 `@layer base` 里的规则对 el-* 组件会**静默失效**。

已补回的基础重置（不要重复添加）：
`[hidden]` 显示、`ul/ol` 去符号、`table` border-collapse、`hr`、`h1-h6` 字号继承、原生按钮与表单控件尺寸归零、`:focus-visible` 焦点样式。

> **页面里不要再写全局 CSS**。需要微调样式时用 `<style scoped>`，且慎用 `:deep()`。

## 三、共享组件（3 个，全部已实测）

### 3.1 `confirmAction` — 确认框

位置：`src/components/ui/confirm.js`

```js
import { confirmAction } from '../../components/ui/confirm'

async function handleDelete(row) {
  const ok = await confirmAction({
    message: `确定删除「${row.nickname}」？此操作不可撤销。`,
    danger: true,           // 危险操作用红色确定按钮
  })
  if (!ok) return            // 取消必须提前 return
  await api.delete(row.id)
}
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `message` | — | 提示正文 |
| `title` | `'请确认'` | 标题 |
| `type` | `'warning'` | 图标类型 |
| `confirmButtonText` | `'确定'` | |
| `cancelButtonText` | `'取消'` | |
| `danger` | `false` | 确定按钮是否红色 |

**行为合同（已实测）**：

- 点「确定」→ 返回 `true`
- 点「取消」、点右上角关闭、按 ESC → 返回 `false`，**不抛异常**
- 其他异常 → `console.error` 后**继续抛出**，不会被吞成「用户取消」

> ⚠️ 必须 `await`。漏掉 `await` 会让确认框失去作用，`if (!ok)` 恒为 false。
> ⚠️ **禁止** `window.confirm` / `window.alert`。

### 3.2 `UiTable` — 表格薄封装

位置：`src/components/ui/UiTable.vue`

```vue
<UiTable :columns="columns" :data="list" :loading="loading" row-key="userId" show-actions>
  <template #toolbar>
    <el-input v-model="keyword" placeholder="搜索昵称" size="small" style="width: 200px" />
  </template>
  <template #role="{ row }">
    <el-tag size="small" :type="row.role === 'SELLER' ? 'success' : 'info'">{{ row.role }}</el-tag>
  </template>
  <template #actions="{ row }">
    <el-button size="small" link type="primary" @click="edit(row)">编辑</el-button>
  </template>
  <template #pagination>
    <el-pagination :total="total" :page-size="size" layout="total, prev, pager, next" />
  </template>
</UiTable>
```

列定义：

```js
const columns = [
  { key: 'userId', label: '用户编号', width: 140 },
  { key: 'nickname', label: '昵称' },                              // 普通列
  { key: 'role', label: '角色', width: 100, slot: 'role' },        // 自定义插槽
  { key: 'extra', label: '格式化', formatter: (row) => row.a + row.b }, // 计算列
]
```

`props`：`columns`（必填）、`data`、`loading`、`rowKey`（默认 `id`）、`emptyText`、`showActions`、`actionsLabel`、`actionsWidth`、`border`、`scrollX`

插槽：`toolbar`、`actions`（作用域 `{ row, index }`）、`pagination`、`empty`，以及按列 `key` 或 `slot` 命名的自定义列插槽

**不做的事**：不接管筛选栏，不发数据请求，不管分页参数字段。那些留在各页面。

> 约定：**表格一律用 `UiTable`，不要直接写 `el-table`**。需要新能力时改建 `UiTable`（找哭女），不要各页自己包一层。

### 3.3 `usePagination` — 分页约定

位置：`src/composables/usePagination.js`

```js
import { usePagination } from '../../composables/usePagination'

const { page, size, total, loading, onPageChange, onSizeChange, afterDelete } =
  usePagination({ defaultSize: 10, onChange: () => fetchList() })
```

**约定（全组统一）**：

- 页码从 **1** 开始；后端若 0 起，在 `api/` 适配层转换，**页面里不要混用**
- 每页条数参数名 `size`，页码参数名 `page`
- 列表接口返回 `{ list, total }`
- 改变每页条数 → 页码重置为 1（已实测，只触发一次 onChange）
- 删除后调用 `afterDelete(剩余总数)` → 当前页超出总页数时自动回退（已实测 page 3→2）

### 3.4 `ElMessage` 统一封装

位置：`src/components/ui/message.js`

```js
import { showSuccess, showError, resolveErrorMessage } from '../../components/ui/message'

try {
  await api.save(form)
  showSuccess('保存成功')
} catch (err) {
  showError(resolveErrorMessage(err, '保存失败'))
}
```

> 函数式调用的组件不会被 unplugin 按需解析，样式已在封装内手动引入。**不要直接 `import { ElMessage } from 'element-plus'`**，否则样式丢失、消息不可见。

## 四、必须保留的行为（踩过的坑）

| 项 | 要求 |
| --- | --- |
| 成功判断 | `Result<Void>` 的 `code=0, data=null` 是**成功**，用 `isOk()` 判断，不能用 `unwrapResult` 有无数据来判断 |
| 金额 | 后端单位是**分**，展示时 `/100`；不要拿组件格式化后的字符串再提交 |
| 取消确认 | 立即 `return`，不提交、不弹错误提示 |
| 请求防重 | 提交按钮 `:loading` + 提前 return；`finally` 恢复状态 |
| 日期 | 选择器输出必须还原为原接口格式，不能把 `Date` 对象直接替换原字符串 |
| 上传 | 只有原本就有上传的页面才迁移；保留原 FormData 字段与限制，避免 `el-upload` 默认 action 与自定义上传双请求 |
| 业务边界 | 不新增后端不支持的功能（商品图片上传、支付渠道选择、删除已有 SKU、批量审核等） |

**禁改文件**：`src/api/index.js`、`src/stores/auth.js`、`src/router/index.js`、`package.json`、`pnpm-lock.yaml`、`src/components/ui/*`、`src/composables/*`、`src/style.css`、`App.vue`、`AppHeader.vue`、`ProductCard.vue`

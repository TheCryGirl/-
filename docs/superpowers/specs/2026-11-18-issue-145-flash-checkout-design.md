# #145 秒杀正式下单计价

## 范围与验收

基线 `main` @ `aa6d696`。沿用现有商品、订单、支付服务与买家确认订单页。秒杀按单活动、单 SKU 单独结算，不混入购物车、不开启优惠券或满减叠加，运费按既有店铺模板计算。仅在隔离数据中验证，不动已运行的演示数据、不发起真实支付。全量测试和前端构建通过后按用户授权快进推送 `main`，核对提交，再关闭 #145。

## 入口、报价与成交金额

- 首页「抢购」进入带活动 ID 的确认订单页，默认数量 1；不再从浏览器请求独立秒杀预占。旧公开预占路由停止写入并提示走正式订单，之前独立生成的记录不转换为已付款订单、不自动重置库存或购买资格。
- 正式预览/创建接受购物车商品或秒杀活动，二者互斥。服务端从商品服务的内部只读接口取得活动对应的商品、SKU、有效单价、数量限制和时段；不接受客户端指定成交单价。验证商品可售、店铺营业、本人不是卖家，并使用当前买家的收货地址。预览不预占任何库存；正式下单拒绝活动过期、售罄、不匹配或价格/应付金额与预览不一致的请求，提示重新预览，不回退成原价成交。确认金额用于比较而不是替代服务端计价。
- 订单明细以分为单位保存秒杀单价与活动 ID 快照（普通订单活动为空）；商品小计加运费等于应付，支付服务按现有方式读正式订单金额，无需信任前端或另做支付链。秒杀订单复用普通订单详情、付款、发货、收货及退款入口，不清理购物车。

## 库存、限购和故障恢复

- 商品服务沿用正式库存预占入口。商详快照、活动价格/时段、SKU 和数量在预占侧重新核对；活动条件扣减、买家限购记录和 SKU 预占同一 MySQL 事务，任一步失败全部回滚。活动记录关联正式订单 ID，保留原有活动+买家唯一约束；同一正式订单重放返回同一预占，另一订单抢同一资格被拒。正式下单幂等标识包含活动、数量、地址和报价条件；订单恢复必须沿用持久化的活动与价格快照，不能变成普通库存预占。
- 订单只有在正式预占成功后才返回成功；未完成预占的秒杀单不视为可支付。已有库存释放事务同步返还活动库存在未付款取消、超时和失败补偿中的占用，并清除该订单的活动限购占用；重复释放不重复回补。付款确认保留活动资格记录；付款后退款走已确认 SKU 回补，不返还活动库存或资格。
- 新数据库由建表脚本初始化；旧数据库只做可重复执行的增量迁移，旧记录和普通订单兼容。接口契约与升级说明随代码同步。

## 验证

覆盖秒杀预览无写入、正式订单和 MOCK 支付金额一致、变价/过期/售罄不按原价提交、SKU 预占失败活动库存不变、同键重放与不同请求并发限购、未付款取消/超时释放、已付款退款保留活动限购，以及普通结算回归。测试不依赖真实资金渠道；最后运行后端聚合验证、Node 前端测试和前端生产构建。

## 3. F01/F02 具体实施步骤

1. 逐字段抄录现有校验：字段名、必填、长度、错误提示、什么时候校验。规则不凭常识添加。
2. 换成el-form与el-form-item，输入绑定原变量；密码可见按钮只是显示能力，不改密码值。
3. 提交前校验，非法输入不调用API；Enter提交与按钮点击共用一个处理函数。
4. 请求期间按钮loading、防止重复进入；成功/失败都在finally恢复状态。
5. 认证成功仍调用原登录态逻辑，沿用原路由返回目标，不一律强跳首页。
6. HTTP200但业务错误、HTTP401、超时/断网均正确展示；不能只在catch处理所有错误。
7. 保留标签与键盘焦点，错误文字与输入关联；不让表单失败导致整页重载或密码出现在日志。

## 4. F03/F04 具体实施步骤

1. 保留原卡片网格，不改成表格；使用哭女维护的ProductCard时保持props与click事件。
2. 首次加载、成功但为空、请求失败三态分开；接口失败不可显示“暂无收藏”。
3. 对现有删除/清理动作接统一confirmAction：返回false立即结束，取消不报错、不发请求。
4. 写成功按原逻辑刷新/移除条目；失败保留原列表。Result<Void> data为空不等于失败，沿用isOk。
5. 逐项忙状态使用业务ID，不用数组下标；删除过程中不影响点击其他商品的ID。
6. 商品不可用、缺图片、长标题、空价格等显示沿用原兜底；不在本页修改公共卡片。

## 5. 每页都要做的手测

| 测试 | 操作 | 预期 |
|---|---|---|
| 登录成功 | 开发账号填写正确凭证→点击/Enter | 一次请求，身份与原返回页面正确，无重复跳转 |
| 登录失败 | 错误凭证、空字段、断网 | 空字段前端拦截；业务/网络失败有提示，不假登录 |
| 重复点击 | 慢网络连续点登录/注册 | 提交期间禁止重复，结束后恢复 |
| 注册规则 | 按原规则取最短/最长/超界值与已有账号 | 仅执行原规则，后端拒绝显示正确；不泄露密码 |
| 登录返回 | 从需登录功能进入登录再成功 | 沿用原目标跳转；无外部URL重定向新能力 |
| 收藏/历史空 | 用无记录账号打开两页 | 显示空态和原有返回浏览入口 |
| 列表加载失败 | 断网/业务失败后重试 | 错误与空态不同，恢复网络可重试 |
| 取消操作 | 点击原删除/清空入口后取消或Esc | 零写请求，无失败toast，记录仍在 |
| 确认操作 | 确认一次再模拟写失败 | 成功按原行为更新；失败不先删本地数据 |
| 卡片跳转 | 点击不同商品卡 | 路由目标为对应productId，不因索引变更串商品 |
| 认证失效 | 过期登录态访问需登录页 | 交原401/路由机制处理，不在本页新增认证实现 |
| 布局/键盘 | 360/768/1440/1920宽度、Tab/Enter/Esc | 无整页横向溢出、焦点清晰、标签不丢失 |

这些测试只使用开发账号；截图遮盖账号隐私，不保存密码/JWT。

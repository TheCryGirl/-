## 二、环境问题的根因与解决

上一轮记录的「容器反复重启」已定位并解决。

### 根因

`docker.service` 使用 `-H fd://`（systemd socket 激活）。该模式在 WSL 下不稳定，导致 dockerd 被周期性重启，容器随之重启。证据：

- `journalctl` 中 `Started docker.service` 的时间戳反复出现
- 容器 `RestartCount` 增长但 `ExitCode=0`（正常退出，非崩溃）
- `OOMKilled=false`，内存充足（15.8 GB，空闲 12 GB）

### 解决

停用 systemd 的 socket 激活，改用独立进程：

```bash
systemctl stop docker.service docker.socket
setsid nohup /usr/bin/dockerd \
  -H unix:///var/run/docker.sock \
  --containerd=/run/containerd/containerd.sock \
  > /var/log/dockerd-standalone.log 2>&1 < /dev/null &
```

改后连续观测 2 分钟，8 个容器全程稳定，dockerd 未重启。

## 附：环境恢复步骤（供后续复现）

```bash
# 1. 启动 dockerd（独立进程方式）
wsl -d Ubuntu -u root -- bash -c 'systemctl stop docker.service docker.socket; \
  setsid nohup /usr/bin/dockerd -H unix:///var/run/docker.sock \
  --containerd=/run/containerd/containerd.sock > /var/log/dockerd-standalone.log 2>&1 < /dev/null &'
sleep 12

# 2. 等 Nacos/MySQL 健康后启动全栈
cd /opt/mall/src/docker
docker compose -f docker-compose.yml -f docker-compose.verify.yml up -d

# 3. 前端连 Docker 网关
cd src/web
VITE_GATEWAY_TARGET=http://localhost:19000 pnpm dev
```
